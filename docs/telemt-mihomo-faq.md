# TeleMT + Mihomo на Keenetic: короткий FAQ

**Короткий ответ:** SOCKS5 в KAS предоставляет Mihomo на порту `7890`. Для TeleMT нужен работающий путь до Telegram DC, но не обязательно отдельный VPN-интерфейс KeeneticOS.

## Как устроено подключение?

Пример размещения обоих сервисов на одном совместимом роутере с Entware:

```text
Telegram-клиент
       ↓ MTProto
TeleMT (входящий порт)
       ↓ SOCKS5, 127.0.0.1:7890
Mihomo (mixed-port)
       ↓ rules → выбранный outbound
Прямой маршрут или внешний прокси/туннель
       ↓
Telegram DC
```

Белый IP или другой доступный вход нужен для подключения внешнего клиента; он сам по себе не обеспечивает доступ роутера к Telegram DC. Входящий MTProto и исходящий транспорт — независимые задачи.

## Частые вопросы

| Вопрос | Ответ |
| --- | --- |
| Какой SOCKS5-сервер рекомендует KAS? | Mihomo, `mixed-port: 7890` (HTTP и SOCKS5). |
| Нужно ли устанавливать SSTP, OpenConnect или WireGuard в KeeneticOS? | Нет, если выбранный исходящий маршрут Mihomo уже обеспечивает доступ до Telegram DC. |
| Нужен ли внешний сервер? | Не всегда. При доступном прямом маршруте достаточно прямого выхода; при недоступном — необходим другой рабочий путь, например существующий прокси или VPN. |
| Обязателен ли SOCKS5 для TeleMT? | Для экспериментального установщика TeleMT MIPSel beta.1 из entware-go — да. Сам upstream TeleMT поддерживает также прямой режим. |
| Что такое `mitun0`? | Виртуальный IP-вход Mihomo (TUN), а не исходящий VPN до конкретного сервера. Для локальной схемы TeleMT → SOCKS5 он не требуется. |
| Нужны ли ProxyN и MagiTrickle? | Не для этого прямого SOCKS5-подключения. Они обслуживают другие способы направления клиентского трафика в Mihomo. |
| Можно ли привязать исходящие соединения к VPN-интерфейсу? | Mihomo поддерживает `interface-name` для proxy-outbound dialer. Конкретный интерфейс KeeneticOS, маршруты и реальный выход нужно проверять; универсальная гарантия работы через любой VPN не заявлена. |
| Нужен ли отдельный ПК или VPS для самого TeleMT? | Нет, если роутер совместим и располагает необходимыми ресурсами. SOCKS5 также может находиться на другом доступном устройстве. |

## Как выбирается исходящий маршрут?

Mihomo выбирает outbound по своему YAML (`rules`, `proxies`, `proxy-groups`). Он может использовать один сервер, несколько серверов с переключением или `DIRECT`, если это предусмотрено конфигурацией. Число серверов не связано с числом TUN-интерфейсов.

`interface-name` задаёт Linux-интерфейс исходящих соединений к proxy-серверам (при необходимости — на уровне конкретного proxy). Это не то же самое, что `bind-address` входящего SOCKS5, выбор outbound или переназначение `mitun0`. Для определения имён интерфейсов есть read-only помощник [mihomo-interface-check.sh](../mihomo-interface-check.sh). Привязка к конкретному VPN требует проверки маршрутов и фактического трафика.

## Что важно при установке?

- KAS устанавливает и интегрирует Mihomo и MagiTrickle, но не устанавливает TeleMT и не выдаёт автоматически рабочие внешние подключения. Bootstrap с одним `mixed-port: 7890` не гарантирует доступ к Telegram.
- Если оба сервиса на одном роутере, обычно достаточно локального SOCKS5. Не открывайте его порт и управляющие API в WAN. При размещении SOCKS5 на другом устройстве ограничьте доступ доверенной сетью и используйте аутентификацию при необходимости.
- Проверяйте отдельно доступность входа TeleMT с клиента, доступность SOCKS5 для TeleMT и фактическое соединение с Telegram DC. Наличие слушающего порта не равно успешной передаче трафика.
- [TeleMT MIPSel beta.1](https://github.com/saymer-alt/entware-go/releases/tag/telemt-mipsel-v3.5.17-beta.1) — экспериментальный отдельный пакет. В релизе подтверждено соединение через SOCKS5 до Telegram DC на физическом KN-1010; это не гарантия универсальной установки или работы на всех роутерах.
