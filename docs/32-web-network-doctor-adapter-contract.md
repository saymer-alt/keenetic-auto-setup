# 32 — Контракт Web-адаптера Network Doctor (issue #323 Этап C, research)

**Статус:** проект контракта для будущих версий KAS WEB (beta.7+). Текущая beta.6 и разрабатываемая beta.7 не затрагиваются. Реализации в этом документе нет — только API/JSON-контракт и границы безопасности поверх уже существующего и проверенного CLI (`kas-network-doctor.sh`, contract `network-diagnostics/v1`, интерфейсные винтажи `--vantage if:DEV` / `--vantage all` из PR #376).

## Принцип

**Один движок — тонкий адаптер.** Никакого второго диагностического движка на Go/JS. Go-слой только: валидация ввода → spawn CLI → потоковая передача отчёта. Вся диагностическая семантика (PASS/FAIL/UNKNOWN/NOT TESTED/UNSUPPORTED, гипотезы, route proof) живёт в CLI.

## API

### POST /api/network-doctor/run

Запуск по явному действию пользователя (кнопка). Никаких фоновых проб при открытии страницы.

Запрос (JSON):

```json
{
  "target": "https://example.com/path",
  "vantage": "if:wan2",
  "dnsServer": "1.1.1.1",
  "noEgress": false,
  "brief": false
}
```

Поля и валидация (fail-closed, всё до spawn):

| Поле | Тип | Правила |
|---|---|---|
| `target` | string | Обязателен, 1–253 символа после нормализации. Только HTTP/HTTPS URL или голый домен/IPv4. Запрещены: схема file/ftp/gopher/telnet и прочие не-http(s); userinfo (`user:pass@`); нечисловой порт; символы вне `[A-Za-z0-9._~:/?#@!&()*+,;=%-]` (тот же класс, что валидирует сам CLI). Пайплайн URL дополнительно: разрешены только `http:`/`https:` и `\u003cдомен или IPv4\u003e[:порт][/путь]`. IPv6-литералы — отказ (CLI тоже отказывает). |
| `vantage` | string | `default` \| `mihomo` \| `if:<dev>` \| `all`. `if:<dev>`: `dev` соответствует `^[A-Za-z0-9._@-]{1,15}$` и **обязан присутствовать в выдаче `--list-vantages`, снятой непосредственно перед запуском** (не из кэша клиента). `mihomo` = текущий SOCKS5h-путь (без отдельного селектора группы). Отдельного «WAN/VPN» селектора нет — только реальные netdev-винтажи; ProxyN/TUN без netdev — UNSUPPORTED на уровне CLI, адаптер пересылает как есть. |
| `dnsServer` | string | Опционален, `^[A-Za-z0-9._:-]{1,60}$`, ровно как CLI `--dns-server`. |
| `noEgress` | bool | Опционален; пробрасывается как `--no-egress`. |
| `brief` | bool | Опционален; человеческий отчёт кратким форматом. |

**SSRF-политика цели (до spawn):** резолв хоста адаптером (чистый DNS-запрос, read-only), каждая полученная A/AAAA-запись проверяется: запрещены loopback (127/8, ::1), link-local (169.254/16, fe80::/10), RFC1918, ULA fc00::/7, multicast, 0.0.0.0/8, metadata-диапазоны (169.254.169.254, fd00:ec2::254). Отказ → `400 target_resolves_to_forbidden_network`. Это **не** распространяется на винтаж `mihomo` (его цель — внешний ресурс по умолчанию; внутренние цели запрещены тем же правилом). Осознанная локальная диагностика — отдельный owner-режим, здесь не проектируется.

**DNS rebinding:** CLI сам резолвит цель заново в момент пробы; адаптерная pre-check — фильтр, а не доказательство. Контракт честен: `route proof`/`egress` из CLI — факты, pre-check — только граница. Redirects CLI не следует (один ограниченный запрос), поэтому redirect-ребиндинг невозможен по построению.

**Shell-инъекция невозможна по построению:** все значения передаются как отдельные аргументы `exec.CommandContext` без shell (`sh -c` запрещён для этого эндпоинта); CLI-флаги — только из белого списка, формируемого адаптером, не из строки запроса. Значение `target` никогда не конкатенируется с флагами.

Ограничения исполнения:

- `Context` с таймаутом: `brief ? 90s : 180s` (верхняя граница бюджета CLI 12+8·N запросов); принудительный kill процесса при превышении;
- один запуск на панель: второй запрос `/run` во время активного получает `409 already_running` (используется существующий слот операций Web; никакой очереди и параллельных проб);
- stdout/JSON CLI каптируется в кольцевой буфер 512 KiB; переполнение → отчёт отбрасывается с `report_truncated: true`;
- никакой ретрай-логики: повтор — явное действие пользователя.

Ответ — при успехе: CLI exit 0/1/3 транслируется как есть; тело — JSON `network-diagnostics/v1` (schema, verdict, facts, vantages[]) + отдельное поле `report_text` (human-отчёт из `--report`) для копирования. Адаптер **не интерпретирует** статусы и не строит собственных выводов.

Ответы-ошибки (JSON `{error: code, message}`): `400 invalid_target|invalid_vantage|invalid_dns|target_resolves_to_forbidden_network`, `409 already_running`, `500 spawn_failed|report_missing|report_truncated`, `504 cli_timeout`. Тексты ошибок не включают raw target (только sanitized form как в CLI).

**Никаких секретов:** `MIHOMO_API_SECRET` не читается адаптером из env ответа и не попадает в отчёт (CLI сам withholding-ит); эндпоинт не возвращает env/конфиг. Доступ к эндпоинту — за существующей аутентификацией панели.

### GET /api/network-doctor/vantages

Возвращает санитизированный вывод `--list-vantages` (dev/src/state, без проб). Кэш запрещён: список снимается на каждый запрос (состояние интерфейсов меняется). Используется формой для выпадающего списка; `if:<dev>` из формы валидируется против этого же свежего списка при `/run`.

### Отмена

`POST /api/network-doctor/cancel` — завершает активный процесс через Context (SIGKILL после grace 3s). CLI спроектирован прерываемым (бюджеты и таймауты внутри), частичный отчёт не публикуется.

## Что адаптер сознательно НЕ делает

- не парсит human-отчёт для решений (только передача);
- не кэширует результаты и не строит историю;
- не добавляет собственные пробы (ping/traceroute/UDP) — их нет в CLI, значит их нет в Web;
- не позволяет запускать произвольные CLI-флаги (только белые поля выше);
- не открывает поток (SSE/websocket) — один запрос, один отчёт; progress — по завершении.

## UX-минимум (для будущей формы)

Поле адреса; селектор винтажа из свежего `/vantages` (+ default/mihomo/all); кнопка «Проверить» с явным disable на время прогона; таблица стадий из `facts` (id, status, detail); блок `vantages[]` с `route_proof` при `all`; кнопка «Скопировать отчёт» (`report_text`); надпись-граница: «Проверка выполнена с роутера и не доказывает путь конкретного LAN-клиента (client.vantage — NOT TESTED)». RU/EN словарь — тот же, что для Doctor-статусов.

## Соответствие существующим границам

- клиентский винтаж остаётся NOT TESTED по построению (#270/#323);
- UDP — UNSUPPORTED CLI → Web показывает UNSUPPORTED, не скрывает;
- никакого auto-fix/restart/apply — эндпоинт read-only по отношению к системе;
- малые RAM: адаптер не держит историю и буферизует ≤512 KiB.

## Готовность к реализации

Контракт сознательно остаётся нереализованным до: (1) merge PR #376 (interface vantages), (2) завершения beta.7-скоупа другим агентом, (3) отдельного owner GO на Web-часть #323 Этапа C. Прототип на mock-данных сознательно не выкладывается — контракт тестабелен без кода (все поля определены, поведение CLI детерминировано и покрыто regression-сьютой).
