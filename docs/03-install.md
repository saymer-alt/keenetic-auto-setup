# 03 — установка (подробно)

Что делает install.sh на самом деле.

Если quick-start — это «вставил и поехал», то здесь:

> **что именно происходит и где может сломаться**

---

## Общий процесс

```id="flow1"
1. Подготовка (opkg, пакеты)
2. bypass_wa policy (создание)
3. Перехват транзитного DNS
4. S00ubifs (RAM режим)
5. Установка Mihomo
6. Bootstrap config.yaml (mixed-port: 7890)
7. Выбор проектного Proxy-интерфейса (ProxyN)
8. Привязка bypass_wa к проектному Proxy
9. Установка MagiTrickle
10. VoIP-хук 020-bypass_wa.sh
11. Watchdog + cron
12. Рестарт Mihomo и самопроверка
```

---

## 1. Базовые пакеты

```bash id="step1"
opkg update
opkg install ca-bundle curl jq nano cron
```

### Зачем

* `ca-bundle` — сертификаты для HTTPS
* `curl` — скачивание всего
* `jq` — парсинг JSON (версии, API)
* `nano` — редактирование конфигов
* `cron` — запуск watchdog по расписанию

### Если ломается

* DNS → смотри `/opt/etc/resolv.conf`
* время → SSL может падать

---

## 2. Настройка bypass_wa policy

```bash id="step2"
ndmc -c "ip policy bypass_wa"
```

### Зачем

Создаётся отдельная политика маршрутизации для помеченного VoIP-трафика —
вне DNS-классификации MagiTrickle.

Куда эта политика ведёт трафик, определяют permits:

* **штатно (автоматически, шаг 8):** через проектный Proxy-интерфейс в Mihomo
* **альтернативно (вручную):** в VPN-интерфейс — ручные permits сохраняются

Без политики у помеченного трафика нет выхода — раздел «Типичные проблемы»
в [05-bypass-wa.md](05-bypass-wa.md).

---

### Перехват транзитного DNS

```bash id="step2b"
ndmc -c "dns-proxy intercept enable"
```

### Зачем

Классические (порт 53) DNS-запросы клиентов, адресованные напрямую внешним
резолверам, перенаправляются в DNS-прокси роутера — иначе они обходят уровень
решений MagiTrickle, и маршрутизация таких устройств тихо выпадает из ваших правил.

* только классический DNS: DoH/DoT не затрагиваются
* установщик применяет это автоматически, сначала проверив текущее состояние

Подробности — в [HOWTO_RU.md, раздел 6.1](HOWTO_RU.md#61-перехват-транзитного-dns-управляется-установщиком).

## 3. Установка S00ubifs (RAM режим)

Файл:

```id="path1"
/opt/etc/init.d/S00ubifs
```

### Что делает

* монтирует:

  * `/opt/tmp`
  * `/opt/var/log`
  * `/opt/var/run`
* в RAM (tmpfs)

### Зачем

* убрать постоянные записи на флешку
* продлить срок жизни накопителя

## 5. Установка Mihomo

```id="step5"
mihomo_*.ipk
```

### Как происходит

1. Ищет `.ipk` нужной архитектуры в релизах `saymer-alt/entware-go` (GitHub API)
2. Если API или jq не сработали — fallback: grep по JSON, повторный запрос, парсинг HTML релизов
3. Скачивает пакет
4. Устанавливает через `opkg`

### Где лежит

```bash id="path2"
/opt/etc/mihomo/
/opt/bin/mihomo
```

### После установки

Создаётся сервис:

```bash id="svc1"
/opt/etc/init.d/S99mihomo
```

---

## 6. Bootstrap config.yaml

Файл:

```bash id="path2b"
/opt/etc/mihomo/config.yaml
```

### Что делает

* если конфига нет — создаёт минимальный bootstrap:

```yaml
mixed-port: 7890
```

* если на месте нетронутый placeholder пакета (он порт входа не задаёт) —
  заменяет его bootstrap'ом; нетронутость определяется по conffile-записи opkg
* существующий пользовательский конфиг — не изменяет никогда

### Зачем

`mixed-port: 7890` — фиксированный контракт проекта: на этом порту слушает
Mihomo, на него смотрят ProxyN и watchdog. Пакетный placeholder порта входа
не задаёт — без bootstrap'а после установки `7890` не слушается.

---

## 7. Выбор проектного Proxy-интерфейса

### Что делает

* ищет среди `Proxy0`, `Proxy1`, … проектный интерфейс — проектным считается
  тот, у которого совпадают **оба** признака: description `mihomo t2sN` и
  upstream `127.0.0.1:7890`
* найденный — использует (повторный запуск новых не создаёт)
* если проектного нет:
  * `Proxy0` свободен → создаёт `Proxy0`
  * `Proxy0` занят чужой конфигурацией → **не трогает его** и создаёт первый
    свободный `ProxyN` (сканирование ограничено первыми 32 номерами)

### Зачем

Это мост:

> Keenetic → Mihomo

Чужой Proxy0 на живом роутере — не редкость (прошлые эксперименты, другие
скрипты). Установщик не угадывает владельца и не переписывает чужую постоянную
конфигурацию.

---

## 8. Привязка bypass_wa к проектному Proxy

### Что делает

* находит политику `bypass_wa` по description `bypass_wa` — имя политики роли
  не играет (может быть `Policy0`)
* добавляет `permit global <ProxyN>` для выбранного на шаге 7 интерфейса,
  если такого permit ещё нет

### Гарантии

* существующие permits не удаляются и не переупорядочиваются — ручная привязка
  к VPN-интерфейсу остаётся рабочей альтернативой
* политика не пересоздаётся
* если политики нет — привязка не создаёт её, а завершается предупреждением
  (политику создаёт шаг 2)

Подробная модель: [05-bypass-wa.md](05-bypass-wa.md)

## 10. Установка bypass_wa

Файл:

```bash id="path3"
/opt/etc/ndm/netfilter.d/020-bypass_wa.sh
```

### Что делает

## 11. Установка watchdog

Файл:

```bash id="path4"
/opt/etc/cron.5mins/mihomo_watchdog
```

И запись в cron:

```bash id="cron"
*/5 * * * * root /bin/sh /opt/etc/cron.5mins/mihomo_watchdog
```

Если в `/opt/etc/crontab` уже настроен `run-parts` для `cron.5mins` — отдельная строка не добавляется.

Установщик также перезапускает cron (`S10cron restart`), чтобы запись применилась сразу.

### Что делает

* проверяет:

  * WAN (двухступенчато: обычные цели → whitelist)
  * порт прокси 7890
  * сквозной туннель SOCKS5h
* при проблеме → рестарт (не чаще раза в 300 сек)

## 13. Диагностика

Скрипт перезапускает Mihomo и выполняет самопроверку всей установки:

* `[ok]` — пункт выполнен
* `[WARN]` — некритично, установка завершена: `[OK] Done (N warning(s))`
* `[FAIL]` — установка **не завершена**, скрипт завершается с ошибкой

Примеры предупреждений:

* `Port 7890 not listening` — Mihomo не запустился или в `config.yaml` нет
  `mixed-port: 7890`
* `Low free space on /opt` — свободно меньше 32 МБ
* `bypass_wa policy has no interface permit` — у политики нет выхода
* `config.yaml not found (bootstrap missing)` — не создался bootstrap

Если всё ок:

```id="ok"
[OK] Done
```

## Где чаще всего ломается

### 1. DNS

```bash id="dbg1"
cat /opt/etc/resolv.conf
```

---

### 2. Время

```bash id="dbg2"
date
```

Если время кривое → SSL не работает

---

### 3. Mihomo не запускается

```bash id="dbg3"
/opt/etc/init.d/S99mihomo status
```

→ почти всегда `config.yaml`

---

### 4. Cron

```bash id="dbg4"
cat /opt/etc/crontab
```

Должно быть:

```id="cronok"
*/5 * * * * root /bin/sh /opt/etc/cron.5mins/mihomo_watchdog
```

---

### 5. Entware

```bash id="dbg5"
which opkg
```

Если пусто — `/opt` не подключён
