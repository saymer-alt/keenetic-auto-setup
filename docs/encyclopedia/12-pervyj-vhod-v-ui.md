# Первый вход в web-панель Mihomo с компьютера (MetaCubeX)

**Сценарий этой статьи:** Mihomo уже установлен по инструкции проекта и работает.
Вы хотите открыть веб-панель (MetaCubeX) с компьютера в домашней сети — и либо видите
портал вида «127.0.0.1:9090» и не понимаете, что с ним делать, либо ничего не открывается.

Понадобится:

- SSH-доступ на роутер под root;
- LAN IP вашего Keenetic (например, `192.168.1.1`). Не знаете, как его узнать —
  сначала откройте [13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md);
- ~10 минут.

Как читать пометки в тексте:

- **Проверено в проекте** — следует из кода установки и разворачиваемого конфига.
- **Общее поведение Mihomo** — факт о ядре/панелях, проверенный по официальному коду
  и документации MetaCubeX (ядро 1.19.x), но не на живом роутере этого проекта.
- Конкретные экраны панелей меняются от версии к версии — ориентируйтесь на смысл
  шага, а не на пиксели.

---

## Шаг 1. Проверить, включён ли controller

> **Проверено в проекте:** установка по умолчанию controller **не включает** — в
> разворачиваемом конфиге `/opt/etc/mihomo/config.yaml` строки `external-controller`,
> `secret` и `external-ui` закомментированы.

Подключитесь по SSH и выполните:

```bash
grep -n "external-controller" /opt/etc/mihomo/config.yaml
netstat -tln | grep 9090
curl -sS http://127.0.0.1:9090/version
```

Как читать результат:

| Результат | Что это значит |
| --- | --- |
| `grep` ничего не вывел или строка начинается с `#` | controller выключен — это **норма**, идите на Шаг 2 |
| `netstat` пусто | порт 9090 никто не слушает |
| `curl` печатает ошибку вида `curl: (7) … Connection refused` | подтверждение: API не запущен |

Принципиальный момент:

> **Если `external-controller` не задан (или закомментирован), API выключен и порт 9090
> не обязан слушаться вообще.** «Панель не открывается» в этом состоянии — не поломка,
> а ожидаемое поведение. «Дефолтного» адреса у контроллера нет; `127.0.0.1:9090` —
> просто конвенция из примеров. (**Общее поведение Mihomo**, проверено по коду ядра.)

## Шаг 2. Включить controller и панель

Откройте конфиг:

```bash
nano /opt/etc/mihomo/config.yaml
```

В конфиге из пакета уже есть закомментированный пример этих строк — найдите его и
замените на:

```yaml
external-controller: 192.168.1.1:9090
secret: "придумайте-длинный-секрет"
external-ui: ui
external-ui-url: "https://github.com/MetaCubeX/metacubexd/archive/refs/heads/gh-pages.zip"
```

Важные оговорки:

- **`192.168.1.1` — это пример.** Впишите фактический LAN IP своего Keenetic.
  Как узнать — [13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md).
- Эти строки должны стоять на **верхнем уровне файла** (с самого начала строки), а не
  внутри другого блока вроде `dns:` или `proxies:`. Удобно отредактировать именно тот
  закомментированный блок, который уже есть. Если такого блока в вашем `config.yaml`
  нет (например, конфиг собран в
  [link-generators](https://github.com/saymer-alt/link-generators)) — просто добавьте
  эти параметры на верхний уровень YAML.
- `secret` — придумайте длинный и свой. Это пароль к API: им панель доказывает, что ей
  можно управлять вашим Mihomo.
- `external-ui: ui` — путь к папке, куда ядро положит файлы панели. Относительный путь
  считается от рабочей директории Mihomo (**Проверено в проекте:** это
  `/opt/etc/mihomo`, так что панель окажется в `/opt/etc/mihomo/ui`). Файлы занимают
  несколько мегабайт на накопителе — на устройствах с малой внутренней памятью
  проверьте место (`df -h /opt`).
- `external-ui-url` — официальный архив панели metacubexd. (**Общее поведение
  Mihomo:** это же значение — встроенный дефолт ядра; указано явно для наглядности.)
- **Не копируйте** закомментированный пример `external-controller: 0.0.0.0:9090` из
  конфига пакета: `0.0.0.0` означает «слушать на всех интерфейсах сразу». Для
  домашнего сценария правильнее LAN IP роутера. И в любом случае — с `secret`.

---

## Шаг 3. Проверить конфигурацию

```bash
mihomo -d /opt/etc/mihomo -t
```

`-t` — проверка конфига **без запуска** Mihomo.

- Успех: ядро печатает сообщение об успешной проверке (точная формулировка зависит от
  версии ядра) и завершается.
- Ошибка: будет назван проблемный элемент конфига — чаще всего отступы (YAML требует
  пробелы, не табуляцию) или опечатка. Исправьте и повторите, пока проверка не пройдёт.

---

## Шаг 4. Перезапустить Mihomo

```bash
/opt/etc/init.d/S99mihomo restart
/opt/etc/init.d/S99mihomo status
```

Ожидаемо: `status` отвечает `alive`.

При первом старте с `external-ui` ядро скачает архив панели в `/opt/etc/mihomo/ui`
(**Общее поведение Mihomo**, авто-скачивание появилось в v1.18.8; в нашей сборке
1.19.27 оно есть). Для этого роутеру нужен доступ к github.com.

---

## Шаг 5. Проверить API с самого роутера

Главное правило этой проверки:

> **Для проверки controller используйте тот адрес, который вписан в
> `external-controller`.** В примере этой статьи это `192.168.1.1:9090`.

```bash
curl -s -H "Authorization: Bearer ваш-секрет" http://192.168.1.1:9090/version
```

Ожидаемо: JSON вида `{"meta":true,"version":"v1.19.27"}` (`meta:true` — признак ядра
mihomo/Meta; версия — ваша).

Три важных замечания:

- Если задан `secret`, запрос **без** заголовка `Authorization: Bearer …` вернёт
  `401 {"message":"Unauthorized"}` — это не поломка, а работа защиты. (**Общее
  поведение Mihomo**, проверено по коду ядра.)
- Почему на роутере в командах часто встречается `127.0.0.1`: этот адрес означает
  «я сам», и он сработает **только если controller привязан к loopback**
  (`external-controller: 127.0.0.1:9090`). В примере этой статьи controller привязан
  к LAN-адресу, поэтому проверяем на нём. Тот же `127.0.0.1` в браузере на компьютере
  означал бы уже сам компьютер. Полный разбор:
  [13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md).
- `Connection refused` на этой проверке почти всегда означает, что curl стучится не на
  тот адрес, где слушает controller, — сверьте его с `external-controller`.

## Шаг 6. Открыть UI с компьютера

Канонический адрес для нашего сценария:

```text
http://192.168.1.1:9090/ui/
```

(подставьте свой LAN IP). Пояснения к «хвостам» адреса:

- `/ui/` — канонический путь, так и пишите;
- `/ui` без слэша тоже работает — ядро само перенаправит на `/ui/` (**общее поведение
  Mihomo**);
- иногда адрес выглядит как `…/ui/#/setup` — часть после `#` не посылается на роутер
  вообще: это внутренняя навигация самой панели (какая страница открыта). Серверу
  важно только `http://IP:9090/ui/`.

Проверить, что файлы панели на месте:

```bash
ls /opt/etc/mihomo/ui     # ожидаем index.html и другие файлы
```

Если папка пуста — панель не скачалась (нет доступа к github.com с роутера): API при
этом работает, а архив панели можно скачать на другом устройстве и распаковать в
`/opt/etc/mihomo/ui` вручную.

Страницу `/ui/` ядро отдаёт без запроса секрета — защищён сам API, а не статические
файлы; не удивляйтесь (**общее поведение Mihomo**).

## Шаг 7. Подключить панель к Mihomo

Открывшаяся страница панели (metacubexd) попросит указать адрес API — и, скорее всего,
предложит вариант:

```text
127.0.0.1:9090
```

> ## ❗ Главное правило этой статьи
>
> **Если панель открыта в браузере на компьютере, `127.0.0.1` означает ваш компьютер,
> а не Keenetic.** Адрес в этом поле браузер использует, чтобы обращаться к API
> Mihomo, — и обращается он с компьютера, а не с роутера.
>
> Замените на адрес вашего роутера:
>
> ```text
> 192.168.1.1:9090
> ```
>
> (или ваш фактический LAN IP), введите `secret` из Шага 2 — и подключайтесь.

Почему так: страница панели — это просто файлы, которые открыл ваш браузер. Все
запросы «к Mihomo» браузер выполняет с вашего компьютера. `127.0.0.1` в этом поле
работает только в двух случаях: на ПК запущен собственный Mihomo, либо проброшен
SSH-туннель (см. статью 13). Даже когда панель раздаётся самим роутером, её
подсказка-дефолт остаётся `127.0.0.1:9090` — это поведение metacubexd (**общее
поведение панелей**, проверено по их коду; интерфейс зависит от версии панели).

---

## Шаг 8. Secret

Поле **Secret** в панели — тот же самый секрет, что вы вписали в `config.yaml`
(Шаг 2), символ в символ: без кавычек и без случайных пробелов.

Если панель отвечает `401` / `Unauthorized`:

1. Проверьте секрет: скопируйте значение из строки `secret:` конфига и вставьте заново.
2. Если меняли `secret` в конфиге — перезапустите Mihomo (Шаг 4), панель должна
   использовать новый.
3. Убедитесь, что подключаетесь к тому порту, который указан в
   `external-controller`.

## Шаг 9. Если UI открылся, но не подключается

| Симптом | Вероятная причина | Проверка |
| --- | --- | --- |
| Connection refused | controller не слушает этот адрес | Шаг 5 с роутера; `netstat -tln \| grep 9090` (какой адрес биндинга?) |
| Долгое зависание / timeout | неверный IP или сеть/firewall | доступен ли сам роутер: открыть его web-интерфейс; `ping` IP |
| `401 Unauthorized` | не совпадает secret | Шаг 8 |
| UI открывается, API не отвечает | в поле панели остался `127.0.0.1` | Шаг 7: заменить на LAN IP роутера |
| HTTPS-страница панели не подключается к `http://…:9090` | mixed content: браузер блокирует HTTP-запросы с HTTPS-страницы | открывайте панель с самого роутера (`…/ui/`) — адрес будет HTTP, как и API |

Не подключается даже после проверок — соберите, что именно происходит (шаг, текст
ошибки, вывод `curl` из Шага 5 и Шага 1), и сверьтесь с
[13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md): почти всегда виноват
адрес `127.0.0.1` в поле панели (или адрес, не совпадающий с `external-controller`).
