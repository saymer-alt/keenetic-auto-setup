# 127.0.0.1 и IP роутера: почему панель не подключается

Эту статью можно читать отдельно от остальных. Она отвечает на один вопрос, который
чаще всего ставит в тупик новичка:

> «Я открыл панель, а там в поле адреса написано `127.0.0.1:9090`. Что сюда вписать —
> и почему не работает?»

Короткий ответ:

> **`127.0.0.1` — это «я сам» для того устройства, на котором выполняется запрос.**
> Если панель открыта в браузере на компьютере, `127.0.0.1` — это ваш компьютер.
> Чтобы добраться до Mihomo на роутере, используйте **LAN IP роутера**, например
> `192.168.1.1:9090`.

---

## Два одинаковых адреса, которые означают разное

`127.0.0.1` есть у **каждого** сетевого устройства — и всегда означает «это же
устройство». Поэтому один и тот же адрес в разных местах указывает на разные машины.

Когда команда выполняется **на роутере** (по SSH):

```text
роутер, SSH:
   curl http://127.0.0.1:9090/version
         │
         ▼
      роутер (тот же роутер) ──► Mihomo ✅
```

Когда адрес открывается **в браузере на ПК**:

```text
браузер на ПК:
   http://127.0.0.1:9090/ui/
         │
         ▼
        ПК  ✗  (Mihomo на ПК нет → «не удаётся подключиться»)
```

Это **два разных `127.0.0.1`**: один принадлежит роутеру, второй — компьютеру.
Запрос никогда не «перепрыгивает» с ПК на роутер только потому, что адрес похож.

> **Общее поведение сетей:** свойство loopback (`127.0.0.1` = «я сам») — базовое
> правило любых IP-сетей, а не особенность Mihomo или Keenetic.

## Как узнать LAN IP вашего Keenetic

`192.168.1.1` — распространённый заводской адрес Keenetic, но это **пример, а не
гарантия**. Ваш роутер может иметь другой адрес (например, `192.168.0.1`). Узнать его
можно любым из способов:

**Windows.** Нажмите Win+R → `cmd` → Enter, затем:

```text
ipconfig
```

В ответе найдите свой адаптер (Wi-Fi или Ethernet) и строку **«Основной шлюз»**
(Default Gateway) — это и есть IP роутера.

**macOS.** В Терминале:

```text
route -n get default | grep gateway
```

**Linux.** В терминале:

```text
ip route | grep default
```

**По имени.** У Keenetic есть фирменный домен: `http://my.keenetic.net` из домашней
сети открывает web-интерфейс роутера (**общее поведение KeeneticOS**, в этом проекте
не проверялось). Сам web-интерфейс роутера тоже подскажет текущий адрес — он виден в
его настройках.

После того как узнали адрес — **везде в инструкциях этого проекта подставляйте именно
его**: в поле панели, в `external-controller`, в командах `curl`. Если ваш адрес
`192.168.0.1`, то правильный адрес панели — `http://192.168.0.1:9090/ui/`.

## Когда `127.0.0.1:9090` в панели — правильно: SSH-туннель

Есть один случай, когда адрес `127.0.0.1:9090` в поле панели использовать **нужно**:
если вы пробросили порт роутера на свой компьютер SSH-туннелем.

```bash
ssh -L 9090:127.0.0.1:9090 root@192.168.1.1
```

(`192.168.1.1` — IP вашего роутера; окно терминала держите открытым, пока работаете
с панелью. В Windows 10/11 SSH-клиент обычно уже встроен — команда работает
в PowerShell или cmd.)

Разбор `-L 9090:127.0.0.1:9090`: левый `9090` — локальный порт **на вашем ПК**; адрес
после второго двоеточия — назначение **на роутере**. Важная оговорка: если в
`external-controller` контроллер привязан не к `127.0.0.1`, а к LAN-адресу (как
рекомендует [12-pervyj-vhod-v-ui.md](12-pervyj-vhod-v-ui.md)), в правой части
используйте этот же адрес:

```bash
ssh -L 9090:192.168.1.1:9090 root@192.168.1.1
```

Иначе туннель будет стучаться в loopback роутера, где никто не слушает, и панель
увидит Connection refused.

Что происходит:

```text
ПК: 127.0.0.1:9090  (панель подключается сюда)
        │
        │  SSH-туннель
        ▼
Keenetic: 127.0.0.1:9090  (роутер обращается «сам к себе»)
        │
        ▼
      Mihomo API
```

Туннель делает так: «когда мой компьютер обратится на свой `127.0.0.1:9090`, передай
это соединение на `127.0.0.1:9090` роутера». После этого `127.0.0.1` в поле панели —
**правильный** адрес: он ведёт на роутер через туннель. Не забудьте ввести `secret`.

Когда это полезно:

- controller включён только на loopback (`127.0.0.1:9090` в конфиге) и вы не хотите
  делать его доступным из сети;
- удалённое управление: добраться до роутера по SSH (например, через VPN до домашней
  сети) — и панель работает, не открывая порты наружу.

## Мини-итог

| Где вы | Адрес для доступа к API Mihomo |
| --- | --- |
| На роутере (SSH, `curl`) | `127.0.0.1:9090` — правильно |
| Браузер на ПК, обычный сценарий | `http://LAN-IP-роутера:9090` — правильно |
| Браузер на ПК **после** SSH-туннеля | `127.0.0.1:9090` — правильно (через туннель) |
| Браузер на ПК, `127.0.0.1` без туннеля | ошибка: это сам ПК |
