# Карта системы: Keenetic ≠ MagiTrickle ≠ Mihomo ≠ MetaCubeX

Эта статья — карта всего, что стоит за Keenetic Auto Setup. Прочитайте её один раз, и
остальные материалы проекта лягут на понятную схему, а не в кучу незнакомых слов.

Главный тезис, который снимает бо́льшую часть путаницы:

> **Keenetic ≠ MagiTrickle ≠ Mihomo ≠ MetaCubeX.**
> Это четыре разные вещи с разными задачами. Ни одна из них не является «другим
> названием» какой-либо из остальных.

---

## Общая схема

```text
Клиент (телефон, ноутбук, телевизор)
   │
   │  DNS-запрос: «на каком адресе youtube.com?»
   ▼
Keenetic DNS ───► MagiTrickle: классифицирует домен по своим правилам
   │
   │  перенаправление выполняют механизмы KeeneticOS (firewall/routing/NAT)
   ├── DIRECT ─────────────────────► провайдер ──► Интернет
   │
   ├── ProxyN (SOCKS5, 127.0.0.1:7890) ──┐
   │                                     │
   └── mitun0 (TUN-интерфейс Mihomo) ────┤
                                         ▼
                                      Mihomo
                                         │
                                         │  proxies / proxy-groups / rules:
                                         │  «какой сервер для этого соединения?»
                                         ▼
                                      Интернет
```

`ProxyN` — проектный proxy-интерфейс Keenetic: `Proxy0`, если он свободен, иначе
первый свободный номер. Занятый чужой конфигурацией `Proxy0` установщик не трогает.

Параллельно трафику, отдельно от него, живёт панель управления:

```text
MetaCubeX (страница в браузере)
      │  HTTP-запросы
      ▼
external-controller (REST API Mihomo, порт 9090 — если включён)
      │
      ▼
Mihomo
```

Панель **трафик не переносит**. Она только смотрит на Mihomo и щёлкает
переключателями через его API.

## Кто есть кто

### Keenetic / Netcraze, KeeneticOS — роутер и его ОС

Названия стоит различать — их часто смешивают:

- **Keenetic / Netcraze** — производители сетевого оборудования (домашние роутеры).
  Для российского региона актуальная линейка развивается под брендом **Netcraze**;
  в этом проекте слово «Keenetic» везде означает такой домашний роутер.
- **KeeneticOS / NDMS** — операционная система роутера. Именно она предоставляет
  базовые сетевые механизмы: маршрутизацию (routing), firewall, NAT, DNS и прочие
  системные сетевые функции. Сегменты, политики подключений (policy routing) и
  DNS-прокси — тоже её механизмы. Установщик проекта включает в KeeneticOS перехват
  транзитного DNS, чтобы запросы клиентов попадали туда, где их видит MagiTrickle.
- **Entware** — среда дополнительного Unix-ПО внутри роутера: в ней живут Mihomo
  и MagiTrickle.

**Чем не является:** KeeneticOS — не «просто коробка с Wi-Fi», но и не прокси: в этой
схеме она не является proxy- или terminating-encryption-слоем пользовательского
трафика (её собственные VPN-туннели — отдельная возможность, вне базовой схемы).

**Где заканчивается ответственность:** когда трафик отдан выбранному интерфейсу-назначению
(провайдер, ProxyN, mitun0, VPN-интерфейс). Что происходит дальше — не её уровень.

### MagiTrickle — автоматизация схемы перенаправления

**Что делает:** наблюдает DNS-запросы, сопоставляет домены с вашими правилами и на
основе этого настраивает и поддерживает правила, по которым механизмы KeeneticOS
(firewall/routing/NAT) направляют трафик выбранного домена в нужный интерфейс:
напрямую (DIRECT), в ProxyN, в mitun0 и т.д.

**Чем не является:** не VPN, не прокси, не proxy-core и не сам firewall — это отдельный
дополнительный компонент. Трафик он не носит: переносят его сетевые механизмы
KeeneticOS. И сама схема «направить часть трафика в ProxyN» возможна и без
MagiTrickle — её пришлось бы настраивать вручную; MagiTrickle автоматизирует настройку
и поддержку этой схемы в рамках своей логики.

**Где заканчивается ответственность:** на доменах, которые до него дошли. Если запрос
клиента не прошёл через наблюдаемый MagiTrickle DNS — правил для этого домена не
появится. Именно поэтому установщик включает перехват транзитного DNS.

### Mihomo — движок маршрутизации («роутер внутри роутера»)

**Что делает:** сетевой/proxy core. Принимает трафик на свои входы — mixed-порт
`127.0.0.1:7890` (прокси) и/или TUN-интерфейс (`mitun0`) — и по своему `config.yaml`
выбирает для каждого соединения outbound: по правилам (`rules`), через группы
(`proxy-groups`: выбор узла, fallback, load-balance) или через конкретный proxy-узел;
в зависимости от конфигурации использует собственные DNS, TUN и sniffing.

После установки в `/opt/etc/mihomo/config.yaml` лежит bootstrap проекта — только
`mixed-port: 7890`; решающий слой (`proxies`/`rules`/`proxy-groups`) появляется,
когда вы кладёте свой рабочий конфиг.

**Чем не является:** не «тот самый VPN на роутере» и не часть KeeneticOS. Для роутера
весь Mihomo выглядит как один локальный SOCKS5-прокси на `127.0.0.1:7890` (интерфейс
ProxyN) и/или как сетевой интерфейс `mitun0`.

**Принципиальная граница:** Mihomo решает, что делать с трафиком, который **уже
попал** в него, — но в базовой схеме сам он LAN-трафик не перехватывает. Чтобы
трафик попал в Mihomo, его должен направить сетевой стек роутера
(firewall/routing/NAT, настраиваемые в том числе MagiTrickle) в локальную точку
входа ProxyN. Это разные роли: *кто направил трафик в Mihomo* ≠ *кто решает, что
с ним делать после попадания*.

**Где заканчивается ответственность:** на выходе к своим серверам. Какие соединения
вообще до него дойдут — определяется схемой на стороне роутера (KeeneticOS и
MagiTrickle), а не им самим.

### MetaCubeX — экосистема, а чаще всего — панель

**Что делает:** MetaCubeX — это организация и экосистема вокруг Mihomo: само ядро
живёт в `MetaCubeX/mihomo`, официальная веб-панель называется **metacubexd**, там же —
гео-базы для правил. В разговорах «MetaCubeX» почти всегда означают именно веб-панель.

**Чем не является:** **MetaCubeX Dashboard — это не сам Mihomo.** Панель — отдельная
страница/программа: интерфейс управления и наблюдения за ядром. Она не является
сетевым core и не переносит через себя пользовательский трафик как прокси. Удалите
панель — Mihomo продолжит маршрутизировать трафик, как ни в чём не бывало.

### controller и web UI — два разных «дополнения» к ядру

**controller** — это настройка `external-controller` в `config.yaml`: она включает
REST API Mihomo (обычно на порту 9090). Через этот API панель получает статистику и
управляет ядром.

**web UI** (dashboard, панель) — страница в браузере, которая к этому API подключается.

В нашей установке панель по умолчанию отсутствует; при включённой `external-ui`
статические файлы панели раздаёт сам Mihomo
([12-pervyj-vhod-v-ui.md](12-pervyj-vhod-v-ui.md)).

Ключевые факты (первый — из конфига проекта, второй — из кода Mihomo):

- **По умолчанию в этом проекте controller выключен**: в разворачиваемом конфиге
  (bootstrap проекта) строк `external-controller`, `secret` и `external-ui` нет вовсе
  (в старом пакетном placeholder они были закомментированы). Не включён
  controller → не работает и API → порт 9090 никто не слушает → панель подключиться не
  может. Это состояние — норма, а не поломка.
- **«Дефолтного» адреса 127.0.0.1:9090 у контроллера нет** — это конвенция из примеров.
  Подробнее: [13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md).

## Роли компонентов одной строкой

Для базовой схемы проекта:

> **KeeneticOS решает, как должен быть направлен трафик роутера; MagiTrickle помогает
> автоматизировать и поддерживать эту схему; ProxyN — точка входа в Mihomo; Mihomo
> решает, как обработать поступивший в него proxy-трафик.**

Это описание именно базовой (proxy-port) схемы. В схеме с TUN точкой перехвата
трафика становится сам Mihomo — [31-tun.md](31-tun.md),
[32-kak-sobrat-kartinu.md](32-kak-sobrat-kartinu.md).

## Почему это важно для новичка

- Mihomo **работает без всякой панели** — установка по умолчанию ставит ровно демон.
- Панель подключается **не к «сайту Mihomo», а к API**, которое нужно сначала включить.
- Адрес `127.0.0.1` в поле панели означает «этот компьютер», а не роутер — самая
  частая точка отказа. Разбор: [12-pervyj-vhod-v-ui.md](12-pervyj-vhod-v-ui.md) и
  [13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md).
