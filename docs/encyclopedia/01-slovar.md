# Минимальный словарь новичка

Это не справочник по всем возможностям Mihomo — официальный есть на
[wiki.metacubex.one/ru](https://wiki.metacubex.one/ru/). Здесь только слова, без
которых нельзя понять ни одну статью этого проекта. Для каждого термина: что это
простыми словами, что это значит **в нашем проекте** и с чем его нельзя путать.

---

## Компоненты

**Mihomo** — ядро (программа-демон), которая принимает трафик и раздаёт его по своим
серверам согласно правилам. *В нашем проекте:* живёт в Entware, запускается скриптом
`/opt/etc/init.d/S99mihomo`, конфиг — `/opt/etc/mihomo/config.yaml`, прокси-порт
`127.0.0.1:7890`. *Не путать:* Mihomo — не приложение с окном и не сайт; всё, что вы
видите в браузере, — это отдельная панель поверх него.

**Clash / Clash.Meta / Mihomo** — одна родословная: оригинальный Clash прекращён в
конце 2023 года, его форк Clash.Meta был переименован в Mihomo. *В нашем проекте:* все
три слова означают одно и то же ядро; в документах проекта написано «Mihomo (Clash
Meta)». *Не путать:* это не три разные программы, которые надо ставить вместе.

**MagiTrickle** — дополнительный компонент в Entware: наблюдает DNS-запросы клиентов,
сопоставляет домены с вашими правилами и настраивает/поддерживает правила, по которым
механизмы KeeneticOS (firewall/routing/NAT) направляют трафик выбранных доменов в
нужный интерфейс (DIRECT, Proxy0, mitun0). *Не путать:* это не прокси и не сам
firewall — трафик переносит сетевой стек KeeneticOS, а не MagiTrickle.

**MetaCubeX** — организация и экосистема вокруг Mihomo: репозиторий ядра
(`MetaCubeX/mihomo`), официальная панель metacubexd, гео-базы. *В разговорах* «открой
MetaCubeX» = «открой веб-панель». *Не путать:* MetaCubeX — не второе название Mihomo;
панель — надстройка, ядро работает и без неё.

**dashboard / web UI (панель)** — страница в браузере для наблюдения и управления
ядером через API: соединения, скорость, переключение серверов. *В нашем проекте:*
по умолчанию не устанавливается и не включается. *Не путать:* панель — не часть ядра и
не обязательный компонент.

**external-controller** — настройка в `config.yaml`, которая включает REST API Mihomo
(адрес вида `IP:9090`). *В нашем проекте:* закомментирована, то есть выключена; без
неё порт 9090 никто не слушает. *Не путать:* это не «адрес панели» и не веб-сервер —
это именно API ядра.

**API** — способ, которым программы разговаривают друг с другом по HTTP. Панель шлёт
запросы к API Mihomo и рисует то, что ядро отвечает. *Не путать:* API — не сайт для
человека: `curl http://IP:9090/version` возвращает служебный JSON, и это нормально.

**secret** — пароль к API контроллера, заданный в `config.yaml`. *В нашем проекте:*
если API доступен из домашней сети — секрет обязателен. *Не путать:* это не пароль
прокси-сервера и не пароль подписки.

## Адреса и сети

**127.0.0.1** — «я сам»: так устройство обозначает само себя (loopback). `127.0.0.1`
на роутере — это роутер, `127.0.0.1` на вашем ПК — это ПК. Подробно:
[13-127-0-0-1-i-ip-routera.md](13-127-0-0-1-i-ip-routera.md). *Не путать:* это не
«магический адрес Mihomo» — это свойство любой сетевой системы.

**LAN IP** — адрес устройства в вашей домашней сети. У роутера Keenetic это чаще всего
`192.168.1.1`, но это не гарантия — проверьте свой (как — в статье 13).

**0.0.0.0** — при настройке «слушать на адресе» означает «на всех сетевых интерфейсах
сразу»: и домашняя сеть, и внешний. *В нашем проекте:* для новичка не рекомендуется в
качестве основного варианта — используйте LAN IP роутера и секрет.

**port (порт)** — номер «двери» на устройстве. *В нашем проекте:* `7890` — прокси-порт
Mihomo, `9090` — порт API (только если включён external-controller).

**bind / бинд** — «на каком адресе и порту программа принимает соединения».
`external-controller: 192.168.1.1:9090` читается так: controller слушает на адресе
`192.168.1.1`, порт `9090` — именно туда и надо обращаться. В наших статьях то же
самое выражено словами «адрес, на котором слушает controller». *Не путать:* бинд —
про **входящие** соединения самой программы, а не про то, куда она отправляет трафик.

## Потоки трафика

**inbound** — вход Mihomo: куда трафик *приходит* к нему. *В нашем проекте:* это
mixed-порт `7890` и/или TUN (`mitun0`). *Не путать:* вход — не выход.

**outbound** — выход Mihomo: куда он *отправляет* соединение — конкретный сервер,
группа или DIRECT. *Не путать:* «направить через Mihomo» всегда значит «Mihomo сам
выбрал один из своих outbound'ов по правилам».

**proxy** — сервер-посредник, через который уходит трафик: VLESS, Reality, Hysteria2 и
др. Перечисляются в секции `proxies` конфига. *Не путать:* любой прокси — это не
обязательно «VPN» в бытовом смысле; и наоборот, слово «VPN» в чатах часто означают
именно прокси-сервер.

**proxy-group** — группа из нескольких proxy с правилом выбора: вручную (`select`),
автоматически по скорости (`url-test`) и т.д. В панели вы переключаете именно группы.

**rule** — строка в `config.yaml`, которая для каждого соединения выбирает outbound:
«домен X — в группу Proxy, остальное — DIRECT».

**DIRECT** — служебный выход «напрямую, без прокси», через обычный интернет роутера.

**REJECT** — служебный выход «запретить соединение»: сайт просто не откроется.

**MATCH** — правило «всё, что не совпало ни с чем выше». Всегда последнее в списке
правил. *Не путать:* `MATCH` в конфиге — не ошибка, это обязательное финальное правило.

**TUN** — виртуальный сетевой интерфейс: Mihomo получает обычный IP-трафик, и
программам не нужны никакие прокси-настройки. *Не путать:* TUN — это режим входа
трафика в Mihomo, а не «тип VPN-подписки».

**mitun0** — распространённое имя TUN-интерфейса Mihomo в Keenetic-сетапах; имя задаётся
в конфиге Mihomo (`tun` → `device`), а Keenetic видит его как обычный интерфейс,
на который можно навести политику. *Не путать:* mitun0 — не деталь MagiTrickle и не
интерфейс Keenetic по происхождению.

**mixed-port** — один порт сразу для HTTP- и SOCKS5-прокси. *В нашем проекте:* это
`7890`; к нему подключается Proxy0 со стороны Keenetic, а браузерные расширения типа
FoxyProxy — после включения `allow-lan: true`
([27-porty-i-config-yaml.md](27-porty-i-config-yaml.md)).

## Данные и источники

**DNS** — «телефонная книга»: перевод доменных имён в IP-адреса. *В нашем проекте* два
уровня DNS, и это разные вещи: DNS Keenetic (его видит MagiTrickle — на нём держится
классификация) и собственный DNS-блок Mihomo в `config.yaml`. Подробнее —
[../../ARCHITECTURE.md](../../ARCHITECTURE.md), раздел DNS-архитектура.

**fake-ip** — режим DNS Mihomo: на запрос домена ядро мгновенно выдаёт временный
адрес из диапазона `198.18.x.x`, чтобы принимать решения по доменам, а не по IP.
*В нашем проекте:* включён в разворачиваемом конфиге по умолчанию. *Не путать:* если
видите в панели соединения на адреса `198.18.x.x` — это не взлом и не ошибка сети, это
так работает fake-ip.

**geodata** — базы «домен → категория/страна» (GeoSite, GeoIP), которыми пользуются
правила `GEOSITE`/`GEOIP`, например `GEOIP,private,DIRECT`. Ядро скачивает базы само.

**provider (провайдер данных)** — источник списков по URL, который Mihomo обновляет
сам: `proxy-providers` (списки серверов) и `rule-providers` (списки правил/доменов).

**подписка** — URL, по которому лежит список серверов (обычно её выдаёт поставщик
услуг). В конфиге подписка обычно подключается как `proxy-provider`. *Не путать:*
подписка — это не протокол и не «сайт»; это просто адрес списка. Собрать конфиг из
своих ссылок и подписок можно в [link-generators](https://github.com/saymer-alt/link-generators).
