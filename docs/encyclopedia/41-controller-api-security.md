# Controller/API Mihomo: bind, secret, удалённый доступ и безопасность

Эта статья продолжает [40-interfejs-metacubexd.md](40-interfejs-metacubexd.md).
Там разобран интерфейс панели; здесь — канал управления, через который панель разговаривает с Mihomo.

> **Controller — административный API ядра.** Доступ к нему нужно защищать как доступ к настройкам роутера, а не как обычную web-страницу.

В базовой установке проекта controller не включается автоматически. Он появляется только после осознанного изменения пользовательского `config.yaml`.

## Что такое `external-controller`

~~~yaml
external-controller: 127.0.0.1:9090
~~~

Это адрес REST API. Через него можно не только читать состояние, но и менять runtime-конфигурацию, переключать прокси, закрывать соединения, перечитывать конфиг и перезапускать ядро.

Официальные источники: <https://wiki.metacubex.one/en/config/general/> и <https://wiki.metacubex.one/en/api/>.

## Bind: адрес перед `:9090`

### `127.0.0.1:9090`

Controller доступен только на самом устройстве с Mihomo. Для Keenetic это самый узкий bind. С ПК в LAN напрямую он не откроется: `127.0.0.1` на ПК — сам ПК.

### `IP-РОУТЕРА:9090`

Controller слушает конкретный адрес роутера. Это удобно для MetaCubeXD из доверенной LAN и уже, чем `0.0.0.0`.

### `0.0.0.0:9090`

Controller слушает на всех IPv4-интерфейсах процесса. Это не означает автоматически «доступен из Интернета» — ещё есть firewall/NAT — но само приложение больше не ограничивает интерфейс. На роутере это широкий bind.

## `secret` — пароль к API

~~~yaml
external-controller: 192.168.1.1:9090
secret: "длинная-случайная-строка"
~~~

API использует `Authorization: Bearer <secret>`. MetaCubeXD передаёт secret при подключении. Если controller доступен по сети, непустой `secret` — нормальный безопасный default.

Не публикуйте secret в GitHub, скриншотах, логах и примерах.

## Что реально может API

Read-only сценарии: версия ядра, список прокси, активные соединения, поток логов, runtime-конфигурация. Наш `mihomo-doctor.sh` использует Controller консервативно и не переключает серверы.

Изменяющие операции включают PATCH runtime-параметров, PUT/reload конфигурации, смену выбранного узла, закрытие соединений, обновление GEO, restart и другие административные действия.

## `/ui/` и API — один контур

При `external-ui: ui` панель доступна на `http://IP:9090/ui/`. UI — статический frontend, команды всё равно идут в API. Защищать нужно сам controller, а не только путь `/ui/`.

## CORS — не firewall и не пароль

`external-controller-cors` управляет browser-origin политикой. CORS не закрывает TCP-порт, не заменяет `secret`, не ограничивает `curl` и не заменяет firewall.

## HTTPS controller

`external-controller-tls` шифрует канал при корректном TLS-конфиге. TLS не отвечает на вопрос «кто должен иметь доступ»: разумный bind, firewall и secret всё равно нужны.

## Безопасный удалённый доступ

Предпочтительный постоянный вариант — сначала VPN в домашнюю сеть, а controller оставить в LAN.

Другой вариант — SSH tunnel при loopback-bind:

~~~bash
ssh -L 9090:127.0.0.1:9090 root@IP-РОУТЕРА
~~~

После этого на ПК открывается `http://127.0.0.1:9090/ui/`.

Прямой port-forward TCP/9090 из WAN не должен быть default: он без необходимости публикует административный endpoint.

## Практические профили

| Сценарий | Bind | Secret | Доступ |
| --- | --- | --- | --- |
| Только shell роутера | `127.0.0.1:9090` | желательно | локально |
| MetaCubeXD из доверенной LAN | конкретный LAN IP | **да** | trusted LAN |
| Несколько доверенных сегментов | `0.0.0.0:9090` только при необходимости | **да** | firewall ограничивает сегменты |
| Удалённо | loopback/LAN | **да** | сначала VPN или SSH |
| Прямой WAN | не рекомендуемый default | недостаточно сам по себе | лучше не публиковать |

## Проверка

Без secret на самом роутере: `curl -sS http://127.0.0.1:9090/version`.

С secret используйте Bearer header, но не вставляйте реальный ключ в публичные скриншоты/логи. Doctor специально не печатает его.

## Граница проекта

`keenetic-auto-setup` не включает controller автоматически, не открывает 9090 в WAN, не задаёт пользовательский secret и не делает UI runtime-зависимостью маршрутизации.
