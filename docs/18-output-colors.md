# 18 — цвета и статусы CLI

Единый визуальный контракт для пользовательского вывода `keenetic-auto-setup`.

## «Светофор»

| Цвет | Статусы / вывод | Смысл |
| --- | --- | --- |
| 🟢 зелёный | `[OK]`, `[ok]`, штатные `[setup]`, `[config]`, `[updater]`, `[migrate]` | нормальный ход операции или успешный результат |
| 🔵 cyan / голубой | `[INFO]`, `[info]` | информация; сама по себе не требует исправления |
| 🟡 жёлтый | `[WARN]` | отклонение или временная проблема, при которой операция может безопасно продолжаться |
| 🔴 красный | `[ERROR]`, `[FAIL]` | фатальная ошибка операции или провал обязательной проверки |

Цвет **не является источником истины**. В каждом сообщении сохраняется текстовый префикс, поэтому вывод остаётся понятным в монохромном терминале, скриншоте, текстовом файле и support-чате.

## WARN не превращается в ERROR из-за неудачной попытки

Промежуточная неудача — ещё не фатальная ошибка. Например, если `curl` получил reset, но затем сработал `wget` или GitHub Contents API fallback, проект пишет жёлтый `WARN` и продолжает работу. Красный `ERROR` появляется только тогда, когда все допустимые пути исчерпаны и операция действительно не может завершиться.

Тот же принцип действует для Doctor: `WARN` означает отклонение, которое не является обязательным текущим отказом; `FAIL` означает провал обязательной проверки по текущему контракту Doctor.

## Где ANSI включён

Цвета выводятся только когда соответствующий поток связан с интерактивным TTY. Если stdout/stderr перенаправлен в файл или pipe, escape-последовательности не добавляются.

Цвет также отключается, если:

```bash
NO_COLOR=1 ...
```

или терминал объявлен как:

```bash
TERM=dumb ...
```

Это позволяет безопасно собирать логи, сравнивать вывод и вставлять его в issue/chat без управляющих символов.

## Логи watchdog всегда plain text

`mihomo-watchdog.sh` пишет постоянный/rotated лог. В него **никогда не добавляются ANSI-коды**. Метки `[OK]`, `[WARN]`, `[INFO]`, `[RESTART]`, `[RATE-LIMIT]`, `[INIT]` остаются обычным текстом, чтобы grep, Doctor и support-анализ не зависели от терминала.

Если watchdog запускается вручную и его лог затем читается через `cat`, сам проект не раскрашивает уже записанные строки.

## S00ubifs

`S00ubifs` исторически имел собственные ANSI-цвета. Теперь они подчиняются тому же TTY/`NO_COLOR` контракту:

- green — `done` / `mounted`;
- cyan — информационное состояние вроде `disabled`;
- yellow — `already mounted`, `already enabled` и другие некритичные состояния;
- red — `failed` / `not mounted`;
- white/default — подписи и нейтральный текст.

## Внешние программы

Проект гарантирует цвета только для **своих status-линий**. Сырой вывод `curl`, `wget`, `opkg`, init-скриптов и других внешних программ может использовать свои цвета или не использовать их вовсе. Мы не перекрашиваем такой вывод и не выводим ANSI в их данные.

## Правило для новых скриптов

Новый пользовательский CLI проекта должен:

1. сохранять текстовые статусы независимо от цвета;
2. использовать green → INFO/cyan → WARN/yellow → ERROR/FAIL/red без новых произвольных значений;
3. не красить recoverable retry/fallback в красный;
4. включать ANSI только для TTY и уважать `NO_COLOR` / `TERM=dumb`;
5. не добавлять ANSI в persistent logs или данные, которые парсятся другими скриптами.

Эти правила закреплены также в [AGENTS.md](../AGENTS.md) и contract smoke tests.
