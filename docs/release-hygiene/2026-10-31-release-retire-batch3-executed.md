## experimental channel: совместимый план миграции (исследование, без реализации)

Фактический протокол выпущенного beta.2-клиента (panel_update.go):
индекс читается с фиксированного URL
`…/releases/download/kas-web-channel-<channel>/panel-update.json`, затем
метаданные кандидата — через Contents API (`releases/tags/<tag>`) со строгой
валидацией (digest/size/URL/state/prerelease). Перенос индекса в другое место —
**изменение протокола уже выпущенного клиента**, поэтому:

- **M1 (сейчас):** индекс остаётся release-asset'ом; `kas-web-channel-experimental`
  сохраняется как действующая инфраструктурная публикация (единственная
  «некрасивая» позиция страницы — осознанный компромисс, запрещено удалять
  до миграции).
- **M2 (beta.3+):** клиент получает fallback-источник индекса — raw-файл на
  отдельной orphan-ветке (`channel/experimental` → raw.githubusercontent.com,
  атомарные коммиты, история, без GitHub Pages). Схема index и вся валидация
  (sha256/binary_sha256/ABI/source_sha/tag-allowlist/API-метаданные релиза)
  не меняются — меняется только транспорт индекса.
- **M3 (после дрейфа флота):** когда панелей beta.2 не остаётся, release-канал
  можно убрать; до этого он остаётся единственным источником для beta.2.

## Долговременное хранение архива (исследование)

Приоритет — сохраняемая проверяемая копия вне истекающих Actions-артефактов:
сейчас это консолидированный архив-релиз (единственная допустимая временная
позиция). Рекомендация на будущее — отдельный публичный репозиторий-архив
(например `saymer-alt/kas-legacy-archive`): страница Releases основного репозитория
остаётся чистой, assets постоянны, проверяемость — по sha256 в ledger; перенос —
копирование assets + запись в ledger, без LFS в основном репо (квоты/клонирование).
