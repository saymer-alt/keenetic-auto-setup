## Исполнимый сценарий удаления (после GO)

`.github/workflows/ops-retire-kas-web-test-releases-batch2.yml`:

- триггер — **только `workflow_dispatch`** (ручной запуск с вводом
  `confirm_delete = "DELETE kas-web-ipk-77ac40e kas-web-ipk-c0dac74"`); push-триггера нет,
  чтобы не повторить сценарий, когда пуш ветки сам выполняет удаление;

  существуют и prerelease → **каждый asset побайтно сверяется с архивом batch-2
  (скачивается из архив-релиза в run)** → теги обоих кандидатов существуют →
  удаление ровно двух release-объектов (`gh release delete`, теги не трогаются) →
  пост-проверка: релизы отсутствуют, теги на месте, архив-релиз цел (5 asset),
  индекс не изменился.

## Способ восстановления удалённого релиза

Тег и коммит не удаляются, поэтому восстановление — создание release-объекта на
существующий тег и залив asset из архива:

```sh
gh release create kas-web-ipk-77ac40e --repo saymer-alt/keenetic-auto-setup \
  --target 2baeed4d880471ff6aa630d6ef04c46c0ea548da --prerelease --latest=false \
  --title '<оригинальное название из prerelease-metadata.json>' --notes '<оригинальные notes>' \
  распаковка-архива/kas-web-ipk-77ac40e/*.ipk распаковка-архива/kas-web-ipk-77ac40e/SHA256SUMS
```

- asset побайтно совпадают (проверено), ссылки `…/download/<tag>/<asset>` снова работают;
- восстанавливаются **не полностью**: numeric release id, дата публикации и счётчики
  загрузок — metadata.json (PR #292, `2026-10-30-prerelease-metadata.json` + архив)
  сохраняет их для ledger.

## Права GitHub и уроки прошлой ошибки

- Удаление release-объекта: `contents: write` (GITHUB_TOKEN в Actions / admin в UI).
  Удаление git-тега — отдельная ref-операция и этим сценарием не выполняется.
- Урок batch-обрезки веток (run 41031195431): workflow удалил 3 ветки и застрял на
  eventually-inconsistent `GET ref` (404 сразу после удаления), попытка автороллбэка
  получила permission-denied. Правила batch-2: (а) удаляются release-объекты, а не refs —
  inconsistent-ref состояния исключены по классу операции; (б) если когда-либо удалятся
  refs — восстанавливать вручную `git push origin <SHA>:refs/heads/<имя>` из
  пользовательского аккаунта, не GITHUB_TOKEN; (в) любой delete-шаг — по одному объекту
  с пост-проверкой, стоп при первой аномалии; (г) перед запуском сверить SHA удаляемых
  объектов с ledger (в документе выше и в workflow).
