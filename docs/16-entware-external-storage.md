# Entware на внешнем USB/SSD: подготовка до запуска проекта

Этот документ относится к ситуации, когда Entware ещё **не установлен**, а `/opt`
нужно разместить на внешнем накопителе Keenetic/Netcraze. Сам
`keenetic-auto-setup` начинает работу **после** появления рабочего Entware/OPKG.

> Важно: установка Entware на внешний накопитель через веб-интерфейс и
> онлайн-установка Entware во встроенное хранилище — это разные сценарии.
> Для внешнего USB/SSD не нужно вводить CLI-команду вида
> `opkg disk storage:/ https://...`.

Официальная инструкция Netcraze для Giga NC-1012:
https://support.netcraze.ru/giga/nc-1012/ru/20980.html

## 1. Подготовьте раздел

Для внешнего `/opt` этот проект поддерживает **только EXT4**.

Если накопитель разбит на несколько разделов, заранее определите, какой именно
раздел будет использоваться под OPKG/Entware. В веб-интерфейсе он будет выбран
как накопитель OPKG.

Проект не форматирует, не конвертирует и не ремонтирует накопитель автоматически.

## 2. Создайте каталог `install`

В корне выбранного EXT4-раздела создайте каталог:

```text
install
```

Для Giga/Netcraze NC-1012 (AArch64) структура должна выглядеть так:

```text
<EXT4-раздел>/
└── install/
    └── aarch64-installer.tar.gz
```

Архив не распаковывайте. Для другой модели используйте архив той архитектуры,
которую указывает официальная инструкция для этого устройства.

## 3. Выберите накопитель в веб-интерфейсе

Откройте:

```text
http://<IP-роутера>/opkg
```

Например:

```text
http://192.168.1.1/opkg
```

В поле **Накопитель** выберите именно тот EXT4-раздел, где находится
`install/<installer>.tar.gz`. При необходимости разрешите доступ нужному
пользователю и нажмите **Сохранить**.

После этого KeeneticOS/Netcraze OS сам монтирует выбранный раздел в `/opt`,
находит installer и запускает установку Entware. Отдельная CLI-команда для этого
сценария не нужна.

## 3.1. Важная ловушка: старая привязка накопителя может выглядеть как рабочая

Если в поле **Накопитель** уже отображается нужный EXT4-раздел, но установка не
стартует и в системном журнале нет новых строк `Opkg::Manager` / `installer`, не
считайте сам факт отображения раздела доказательством, что новая установка была
запущена. После предыдущей попытки в интерфейсе может оставаться старая сохранённая
привязка.

В таком случае безопасный способ заново инициировать выбор накопителя через GUI:

1. в **Менеджере пакетов OPKG** выберите **Не выбран**;
2. нажмите **Сохранить**;
3. дождитесь, пока изменение полностью применится;
4. снова откройте поле **Накопитель**;
5. заново выберите нужный внешний EXT4-раздел, где лежит
   `install/<installer>.tar.gz`;
6. проверьте доступ нужного пользователя, например `admin`;
7. нажмите **Сохранить** ещё раз;
8. сразу откройте системный журнал и проверьте появление новых строк установки.

Ожидаемый признак реального старта — новые записи `Opkg::Manager` / `installer`
и этапы `[1/5]`, `[2/5]` и далее. Если их нет в течение короткого времени после
повторного сохранения, проблема всё ещё не в "долгой установке": установка не
стартовала, и нужно снова проверить раздел, папку `install`, installer-файл и
сетевую доступность.

## 4. Откройте системный журнал и дождитесь конца установки

Сразу откройте **Диагностика → Системный журнал**. Не перезагружайте роутер и не
пытайтесь вручную запускать Entware, пока установка не завершена.

Нормальная установка проходит этапы вида:

```text
[1/5] ...
[2/5] ...
[3/5] Generating SSH keys...
[4/5] Setting timezone, script initrc and starting "dropbear"...
[5/5] "Entware" installed!
```

Перед финалом обычно видны установка базовых пакетов (`zoneinfo-europe`,
`opt-ndmv2`, `dropbear`, `poorbox`, `busybox`), затем генерация ключей RSA,
ECDSA и ED25519.

Критерий успеха — именно финальная запись:

```text
[5/5] "Entware" installed!
```

Если после сохранения накопителя этапы `[1/5] ... [5/5]` вообще не появляются,
проверьте:

1. выбран ли правильный раздел;
2. действительно ли его файловая система EXT4;
3. существует ли каталог `install` в корне раздела;
4. лежит ли внутри правильный installer-архив;
5. доступен ли Интернет и разрешается ли `bin.entware.net`.

## 5. Для установки на внешний диск CLI роутера не нужен

Для USB/SSD-сценария установка Entware выполняется через **Файлы и папки** +
**Менеджер пакетов OPKG**. Входить в CLI роутера ради установки не требуется:

- не нужен Telnet;
- не нужен SSH на порт 22;
- не нужно вручную выполнять `opkg disk ...`;
- не нужно запускать installer из CLI.

Если папка `install` подготовлена правильно, нужный накопитель выбран в OPKG и
нажато **Сохранить**, дальше нужно смотреть системный журнал и ждать финального
`[5/5] "Entware" installed!`.

### Если CLI роутера всё-таки нужен для другой задачи

Web CLI можно открыть прямо из веб-конфигуратора, добавив `/a` к адресу роутера:

```text
http://<IP-роутера>/a
```

Например:

```text
http://192.168.1.1/a
```

Это CLI **самого роутера**, а не Entware shell. Для установки Entware на внешний
накопитель этот шаг всё равно не нужен.

Также можно войти по штатному SSH KeeneticOS/Netcraze OS:

```text
порт: 22
логин: пользователь роутера (например admin)
пароль: пароль этого пользователя
```

Например:

```bash
ssh admin@192.168.1.1
```

При первом SSH-подключении OpenSSH может запросить подтверждение host key. На
вопрос `Are you sure you want to continue connecting (yes/no/[fingerprint])?`
нужно ответить полным словом `yes`, а не `y`.

На современных macOS команда `telnet` может отсутствовать. Устанавливать Telnet
только ради этого сценария не нужно.

### Не путайте SSH роутера и SSH Entware

До установки Entware SSH самого роутера и SSH Entware — разные сервисы.
Штатный SSH на порту 22 приводит в CLI роутера, а не в Entware shell.

### SSH Entware

Только после успешной установки Entware запускается отдельный `dropbear` из
`/opt`. В текущей официальной инструкции первичный вход для этой установки
показывается в системном журнале; типичный initial state:

```text
логин: root
пароль: keenetic
порт: 222
```

Ориентируйтесь на финальные строки журнала конкретной установки и после первого
входа смените пароль/порт по своей политике.

## 6. Если в журнале есть ошибки DNS

Ошибки `https-dns-proxy` и ошибки Entware installer — не одно и то же.
Например, HTTP `404` от DoH означает, что HTTPS-сервер доступен, но URL DoH
задан неверно или без нужного endpoint path.

Для диагностики сначала проверьте:

- корректность текущего DoT/DoH профиля;
- обычное DNS-разрешение `bin.entware.net`;
- системное время роутера;
- доступность Интернета с самого роутера.

Не меняйте одновременно storage, DNS и маршрутизацию без необходимости: это
усложняет поиск причины.

## 7. После Entware

Когда в журнале появилось `[5/5] "Entware" installed!`, войдите в Entware shell
и только после этого переходите к установке проекта:

```bash
opkg update && opkg install curl && \
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-auto-setup/stable/setup.sh | sh
```

Дальше `setup.sh` и `install.sh` самостоятельно проверят фактический `/opt`,
EXT4, компоненты KeeneticOS, RAM/swap и остальные требования проекта.
