# Практический MagiTrickle-конфиг: field sample

Это **реальный пользовательский экспорт MagiTrickle**, который Saymer использует как
рабочую основу на клиентских роутерах. Он добавлен в репозиторий как практический
пример и исходный материал для будущих списков доменов/подписок.

Файл:

- [`saymer-field-2026-09-27.mtrickle`](examples/magitrickle/saymer-field-2026-09-27.mtrickle)

## Что внутри

Снимок на 2026-09-27 содержит:

- **8 групп**;
- **287 правил**;
- **217** правил `namespace`;
- **48** правил `subnet`;
- **11** правил `domain`;
- **9** правил `wildcard`;
- **2** правила `regex`.

Группы:

1. `2IP Test Apple`
2. `Chat AI GEO Block`
3. `YouTube Google`
4. `TikTok Netflix`
5. `WA FB Meta Instagram`
6. `Telegram`
7. `*.com` — экспериментальная группа, в самом экспорте отключена
8. `Blackhole ADS Tracking`

Семь обычных групп используют **`mitun0`** как выход в Mihomo; группа блокировки
использует `blackhole`.

## Важная оговорка

Это **не официальный список доменов сервисов**, не эталон и не гарантия полноты.
Конфиг накоплен в реальной эксплуатации: часть правил собиралась из разных
сообществ/чатов, часть — по практическим наблюдениям и проверкам сервисов.

Домены, CDN, API, ASN и IP-сети со временем меняются. Поэтому:

- рабочий сегодня домен завтра может стать ненужным;
- сервис может добавить новый API/CDN/auth-домен;
- широкие правила могут захватывать больше трафика, чем ожидает другой пользователь;
- наличие правила в этом файле означает **полевое использование**, а не официальную
  принадлежность домена конкретному сервису.

Особенно осторожно относитесь к широким правилам вроде общих CDN/облачных сетей,
целых доменных зон и крупных subnet/ASN-диапазонов. Они могли быть оправданы в
конкретной сети, но не должны автоматически переноситься в «минимальный» список
для всех.

## Как использовать

### Вариант 1. Импортировать как рабочую основу

Откройте MagiTrickle:

```text
http://<IP-роутера>:8080/
```

и выполните **Import Config** этого `.mtrickle`-файла.

Перед импортом сохраните свой текущий конфиг через **Export Config**, если он уже
настроен.

После импорта проверьте:

1. что `mitun0` существует в текущем `config.yaml` Mihomo;
2. что нужные группы включены;
3. что сервисы действительно работают через ожидаемый путь;
4. что широкие subnet/wildcard/regex правила вам действительно нужны.

### Вариант 2. Использовать как источник идей

Более безопасный путь для нового пользователя — не импортировать весь файл, а
взять из него только нужные сервисы/домены и собрать собственные группы по
[практической инструкции в HOWTO](HOWTO_RU.md#64-как-собрать-список-доменов-и-создать-свою-группу-с-нуля).

## OpenCCK, браузерные наблюдения и community-списки

OpenCCK — только **один** из возможных источников. Практический список обычно
собирается из нескольких источников:

- открытые базы вроде OpenCCK;
- браузерные/network-наблюдения за тем, к каким доменам обращается сервис;
- community-списки и обсуждения;
- собственная эксплуатация: «какая функция перестала работать без конкретного домена».

Ни один из этих источников сам по себе не гарантирует полноту.

## Подписки MagiTrickle

MagiTrickle умеет работать с подписками на удалённые списки. Это удобно, если
пользователь хранит свой список в GitHub/Gist или на другом HTTP-ресурсе и хочет
обновлять его на нескольких роутерах из одного места.

Этот репозиторий **пока не объявляет данный field sample публичной поддерживаемой
подпиской**. Здесь сохранён полный `.mtrickle`-экспорт как исходная полевая база.

Следующий логичный шаг — при необходимости выделить из него отдельные небольшие
raw-списки по сервисам, например:

```text
OpenAI / ChatGPT
Gemini / Google AI
Claude
YouTube
Telegram
Meta / Instagram / WhatsApp
TikTok
Netflix
Apple
```

и только после ревизии каждого списка решить, какие из них имеет смысл публиковать
как удобные URL для MagiTrickle subscriptions.

## Принцип сопровождения

При изменениях не надо «чистить» этот исторический снимок задним числом. Если
появится новая проверенная версия, лучше добавить новый датированный snapshot или
отдельные актуализируемые списки. Так сохраняется разница между:

- **field evidence** — что реально использовалось;
- **current maintained list** — что сейчас считается актуальным;
- **official source** — если сам сервис когда-либо публикует собственный перечень.
