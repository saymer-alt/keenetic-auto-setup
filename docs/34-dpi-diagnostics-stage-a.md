# 34 — DPI-диагностика Network Doctor: Stage A (исследование и дизайн, issue #455)

**Назначение документа:** зафиксировать Stage A по [issue #455](https://github.com/saymer-alt/keenetic-auto-setup/issues/455) — какие измерения добавим в `kas-network-doctor.sh` (P1), что из этого доказуемый факт, что гипотеза, что `UNSUPPORTED` при имеющихся инструментах, и как это ложится в контракт `network-diagnostics/v1` аддитивно. **Это дизайн, не production-код**: реализация — отдельные PR Stage B с `Refs #455` и ГО/NO-GO-гейтами.

**Upstream-источник:** [Runnin4ik/dpi-detector](https://github.com/Runnin4ik/dpi-detector), изучено на exact SHA `8d6d25a733f82e97a2aad8435072f8a1e3e43958` (main, 2026-11-08), лицензия MIT. **Код upstream не копируется**: Python/asyncio/httpx не переносится на роутер; заимствуются только алгоритмические идеи, переосмысленные под POSIX sh/BusyBox/Entware. Отдельно перечислены утверждения upstream, которые KAS сознательно **не** копирует из-за переобобщений.

## Заимствованные алгоритмы upstream (проверено на SHA `8d6d25a`)

| Идея upstream | Где | Суть | Адаптация для KAS |
| --- | --- | --- | --- |
| Эхо-проба резолвера | `core/dns/udp.py` | A-запрос `whoami.akamai.net` к конкретному IP:53 — авторитетный ответ даёт адрес рекурсивного резолвера, который реально сходил наружу (для DNS-релея — IP его upstream) | P1: `dns.resolver-egress` через BusyBox `nslookup whoami.akamai.net <server>` — без ручного DNS-wire. Факт: полученный A-ответ как наблюдение. Гипотеза: «это и есть реальный наружный резолвер» (CNAME-цепочки, anycast-группировка /24) |
| Двухфазное сравнение DNS | `core/dns_scanner.py` | Фаза A — доверенные домены (список настраиваемый), фаза B — проблемные; ответы UDP/53 сравниваются с эталоном DoH | P1: сравнение ответов по одному целевому домену между источниками (системный резолвер / явный UDP/53 / DoH) — `dns.answer-consistency`. Доверенные домены — не часть P1 (бюджет); список-заготовка фиксируется для P2 |
| Ручной DNS-wire-парсер | `core/dns/wire.py` | Rcode из flags&0xF: 3=NXDOMAIN; A/AAAA-записи; TXT | На sh не переносится в общем виде; P1 обходит: JSON-вариант DoH (см. ниже) и текст BusyBox nslookup. Ограничение честно отражено в матрице |
| DoH-классификация ошибок | `core/dns/doh.py` | SSLError/ConnectError → «BLOCKED», остальное → «ERROR» | **Не копируется как вердикт.** «BLOCKED» = факт ошибки соединения/сертификата DoH-конца; «перехват DoH» — только гипотеза (сама гипотеза легитимна, категория — нет) |
| Классификация TCP/TLS-стадий | `utils/error_classifier.py` | Различение: RST на ClientHello, EOF (тихий обрыв), TLS alert (unrecognized_name / handshake_failure / protocol_version), SPOOF (wrong version/garbage), обрыв после передачи | P1: `tls.stage-class` / `tcp.stage-class` по exit-кодам и строкам ошибок curl. Атрибуция стадий — факт (где остановился curl); смысловые ярлыки upstream («RST на ClientHello», «MITM») — только гипотезы |
| Ступенчатая отдача 16–20 КБ | `core/tcp16_scanner.py` | 10×4 КБ ступенями с `X-Pad`; ступень 0 — чистый запрос живости; отказы **ниже** порога (~12 КБ) = «обычный обрыв»; DETECTED только в детект-диапазоне | **P2 (opt-in, отдельный GO).** Переносится дисциплина: контрольная серия, порог детект-диапазона, повторное подтверждение, счётчики bytes. Ни одного вердикта «DPI» по одному отказу |

**Upstream-переобобщения, которые KAS не копирует:** `TLS MITM` для expired/self-signed/hostname-mismatch (это классы отказа проверки сертификата, не доказательство MITM); «EOF в хендшейке = в 99% RST» (полезная гипотеза, не факт); «SSLError на DoH = BLOCKED/подмена» (см. выше); отождествление TLS-версии/CDN-поведения с DPI.

| --- | --- | --- | --- |
| Системный резолвер | A/AAAA-ответы, их адреса, таймаут/ошибка текста nslookup; «ответы различаются между источниками» | перехват, split-horizon, geo-CDN | «DNS подменён» по одному расхождению |
| Явный UDP/53 (`--dns-server` или внешний) | те же ответы от указанного IP; отсутствие ответа/таймаут | блок UDP/53, hijack порта 53 | заявлять «UDP/53 заблокирован» без отличия timeout/refused |

| Согласованность источников | множества ответов равны/различаются (по-семейство A/AAAA) | hijack, CDN-разброс | смешивание IPv4/IPv6 в одном сравнении |

| TCP-стадия | exit curl, стадия останова (connect/handshake/read), telnet-стадия закрытия | RST-атрибуция, MTU, DPI | `curl 35/56/28` = «блокировка» без доп. свидетельств |
| TLS-стадия | класс отказа сертификата (60/19: время/CA), alert-строка из ошибки curl как текст, verdict стадии | SNI-block, протокольный downgrade, MITM | ярлыки upstream «TLS MITM/DPI» как статусы |

## Семантика vantage/egress (фиксируется точно)

- `--noproxy '*'` убирает только влияние env-прокси. Он **не доказывает физический direct-WAN**: netfilter/MagiTrickle/policy routing/интерфейсные политики могут перехватывать пакеты и на роутере. Следствие: любое direct-наблюдение P1 подписывается как `route: unproven` по умолчанию; `egress-distinct`/`same-as-default` — только от фактического egress-наблюдения (сегодняшний `egress.direct`, усиленный #452).
- Тест с роутера не доказывает путь LAN-клиента: `client.vantage` остаётся `NOT TESTED`.
- P1-пробы не меняют и не выбирают интерфейсы/политики; если #452 слит, расширенные пробы исполняются под тем vantage, что выбрал пользователь, и в JSON подписывают его; если нет — `vantage: router` как сегодня.

## Аддитивное расширение `network-diagnostics/v1`

Совместимость: все существующие `checks[].id`, статусы `PASS/FAIL/UNKNOWN/NOT TESTED/UNSUPPORTED`, exit-коды `0/1/2/3`, поля `schema/version/timestamp/verdict/target/vantage/budget/egress/counts` — без изменений. Парсер doctor-report.js не затрагивается.

- **Новые check-id (стабильные):** `dns.udp53` (явный сервер), `dns.resolver-egress` (whoami-эхо), `dns.doh` (JSON DoH), `dns.dot-transport` (только TLS до :853), `dns.answer-consistency`, `dns.ip6` (AAAA отдельно), `dns.interception-local`, `tcp.stage-class`, `tls.stage-class`. Существующие id (`dns.router`, `dns.custom`, `tcp.connect`, `tls.handshake`) не переименовываются и не меняют семантики.
- **Новые опциональные поля в `checks[]`** (отсутствие поля в старых прогонах = валидно): `observed.stage` (connect/handshake/read/close), `observed.exit_code`, `observed.answer_set` (обезличенные адреса, по-семейство), `observed.source` (заданный endpoint как введён, без секретов), `observed.latency_ms`. Всё — наблюдения, никакой интерпретации.
- **Расширение `budget`:** `profile` (`default` | `extended`), `cap`, фактические счётчики остаются. Новые top-level массивы не вводятся (гипотезы остаются внутри вердикта, как сегодня).
- **Маскирование:** правила docs/29 распространяются на новые выводы: URL DoH печатается как `https://<host>/[query withheld]`; userinfo/токены исключены; имя домена-цели разрешено (это цель пользователя); ответы DNS — только адреса, без сырого вывода утилит с потенциальными посторонними записями (сырое observed — обрезанное и отфильтрованное).

## Бюджет расширенного профиля

- Дефолтный запуск **не меняется**: ≤12 запросов, текущие таймауты.
- `--extended-dns` (Stage B, opt-in): кап +6 DNS-проб (whoami-эхо ×2: системный и явный сервер; DoH ×2; сравнение ×2 — суммарно не более), per-probe таймауты: UDP/53 — 6 c через `timeout`, DoH — 10 c (`--connect-timeout 6`), общий wall-clock-кап печати в отчёте. Счётчик фактического расхода показывается как сегодня (REQUESTS_USED/MAX). Отсутствие инструментов уменьшает фактический расход и помечает проверки `UNSUPPORTED` — кап не «съедается» пустыми попытками.

## Что НЕ делается (границы Stage A/B)

- Никаких production-изменений в этом PR: только этот документ.
- Не строится второй DPI-сканер, не копируются списки доменов и bypass-детектор upstream (P3 R&D — отдельный дизайн).
- Никаких авто-исправлений DNS/маршрутов/MT/Mihomo, никаких фоновых проб, никакого `--insecure`/`CERT_NONE` в штатной TLS-проверке; специализированная MITM-диагностика — вне рамок до отдельного security-ревью.
- CI ≠ FIELD: полевые пробы — отдельный owner-GO этап на реальном Keenetic (read-only), результаты фиксируются как FIELD, не как CI-PASS.
