# KAS Control Center — установка и работа с тестовой WEB-панелью

**KAS Control Center** — отдельный, необязательный WEB-компонент для уже установленного [Keenetic Auto Setup](../README.md). Он не заменяет KAS Core и не переустанавливает Mihomo/MagiTrickle: позволяет просматривать состояние, запускать Doctor, импортировать YAML через штатный механизм KAS, управлять исключениями в подписках и вручную проверять обновления.

**Важно о версиях.** Тестовые выпуски Web часто сменяются, поэтому эта инструкция не содержит фиксированного номера беты и URL конкретного IPK. Актуальную установочную версию выбирают **по текущему опубликованному Web prerelease**, а не по прошлой инструкции. Архивные версии не поддерживаются в качестве способа новой установки.

**Если панель уже установлена** (начиная с выпусков, читающих GitHub Pages), основной путь обновления — **кнопка проверки обновлений в самой панели** (карточка «Обновление панели», канал «Бета»): она предложит актуальный prerelease, проверит SHA256 и спросит подтверждение. Ручная установка IPK из Release ниже нужна для **первой установки** и для восстановления, когда панель недоступна.

## Требования и ограничения

- Keenetic/Netcraze с Entware, SSH и работающим KAS. Для штатного запуска Web необходим IPv4 на интерфейсе управления `br0`; название пользовательского сегмента в KeeneticOS значения не имеет.
- Проверить фактическую архитектуру Entware командой `opkg print-architecture`. Поддерживаемые варианты IPK: `aarch64-3.10`, `armv7-3.2`, `mipsel-3.4`, `mips-3.4`. Не выбирать архитектуру по приблизительному названию роутера.
- В текущая версия Web новая установка WEB слушает **все IPv4 роутера** на TCP **18080**. Если порт занят (`EADDRINUSE`), автоматический выбор пробует **18081–18090** и сохраняет фактический порт. Ранее сохранённый порт имеет приоритет, даже если это 8081.
- По умолчанию **нет пароля и TLS**. Привязка к `br0` сама по себе не запрещает доступ из других маршрутизируемых сетей. Не публикуйте Web через открытый WAN/port forwarding; ограничьте доступ доверенными управляющими сетями. Basic Auth по обычному HTTP не шифрует пароль.
- У Web нет автоматического отката IPK. Не используйте `opkg --force-*`, не выключайте питание во время установки и сохраняйте резервную копию настроек и YAML перед обновлением.

## Где взять актуальный IPK

1. Откройте [**GitHub Releases проекта**](https://github.com/saymer-alt/keenetic-auto-setup/releases).
2. Найдите **актуальный prerelease KAS Control Center / KAS WEB**, предназначенный для установки пользователями. **Не используйте GitHub «Latest»**: он относится к стабильному релизу **KAS Core**, а не к Web-панели.
3. На роутере выполните `opkg print-architecture`. Скачайте **один** соответствующий архитектуре IPK из выбранной публикации и файл `SHA256SUMS` **из той же публикации**.
4. Перенесите оба файла в отдельный каталог на роутере через SCP/SFTP либо скачайте их с доверенной машины. Не смешивайте файлы из разных релизов и не переименовывайте IPK.
5. Проверьте контрольную сумму до установки. `SHA256SUMS` может содержать относительные пути вида `./имя-файла`, поэтому нельзя полагаться на простой grep без учёта этого префикса.

Ниже пример **без привязки к версии и ABI**. Он предполагает, что в каталоге `/tmp/kas-web-install` находятся **ровно один выбранный IPK** и соответствующий `SHA256SUMS`:

```sh
cd /tmp/kas-web-install || exit 1
set -- kas-control-center_*.ipk
[ "$#" -eq 1 ] && [ -f "$1" ] || { echo "Ожидается ровно один IPK"; exit 1; }
IPK=$1
awk -v name="$IPK" '
  $2 == name || $2 == "./" name { print; found++ }
  END { if (found != 1) exit 1 }
' SHA256SUMS > selected.sha256 &&
sha256sum -c selected.sha256 &&
opkg install "./$IPK"
```

Проверка должна показать `OK`. Если файл не найден в `SHA256SUMS`, хеш не совпадает или архитектура не подходит — **не устанавливать**. `sha256sum` подтверждает соответствие скачанного пакета опубликованному списку, но не заменяет доверия к самому источнику.

После успешной установки:

```sh
sh /opt/etc/init.d/S98kas-control-center start
sh /opt/etc/init.d/S98kas-control-center status
opkg status kas-control-center
```

Запускать службу нужно явно после установки. Откройте `http://<IPv4-адрес-роутера>:18080/` (либо фактически выбранный порт в status) или ранее сохранённый порт. Убедитесь, что версия установленного IPK и работающей панели согласованы.

Если GitHub недоступен непосредственно с роутера, скачайте проверенные файлы на доверенном ПК и перенесите их SCP/SFTP. Не выполняйте случайные скрипты из альтернативных источников.

## Работа в WEB

- **Обзор** — версии KAS, панели, Mihomo и MagiTrickle, ручная проверка обновлений.
- **Подписки** — список серверов подписок и исключение выбранных узлов через штатный импортёр KAS; проверьте также возможность снять исключения.
- **Конфигурация** — вставка или загрузка полного YAML через штатный импортёр; перед изменением сделайте резервную копию.
- **Диагностика** — запуск Doctor и сводка результатов, включая предупреждения и ошибки.
- **Настройки** — язык, тема, порт и параметры доступа; конкретные элементы могут меняться в тестовых выпусках.

В карточке обновления Web выберите **Бета** или **Стабильный** и нажмите проверку версии. Смена канала сама ничего не устанавливает, обновление запускается только после подтверждения владельца. Наличие версии на канале зависит от того, опубликован ли соответствующий выпуск; GitHub «Latest» для выбора Web здесь не применяется.

После применения обновления убедитесь, что **установленная и работающая версии** совпадают, Web снова доступна, а YAML, Doctor, фильтры и доступ клиентов сохранились. На некоторых тестовых сборках открытая страница могла показывать старую версию до принудительного обновления браузера: это известное ограничение интерфейса, а не доказательство неудачной установки; проверяйте состояние службы отдельно.

## Статусы служб: что означают цвета и значки

Начиная с beta.8 карточка «Состояние» показывает состояние **процессов** Mihomo и MagiTrickle — по факту работы исполняемых файлов, а не по доступности Интернета у клиентов:

| Цвет и значок | Состояние | Что это значит |
|---|---|---|
| зелёный ✓ | Процесс запущен | Подтверждённое свежее наблюдение `runtime.state=running`. **Не означает**, что через прокси работают сайты у ваших устройств |
| красный ✕ | Процесс остановлен | Подтверждённый `stopped` — процесс есть на диске, но не работает |
| красный ✕ | Не установлен | Подтверждённый `absent` — исполняемого файла нет; это не общесистемная авария |
| янтарный ? | Не удалось определить | Состояние процесса неизвестно |
| нейтральный – | Снимок устарел / нет данных | Ответ не получен, недействителен или старше 15 минут; нажмите «Обновить» |

Цвет дублируется значком и текстом, поэтому читается в обеих темах и при дальтонизме. Заголовок карточки показывает точный статус: «Состояние процессов обновлено: {время}», код ошибки (например, `HTTP_503`) при неудаче или «Снимок состояния процессов устарел» — обновите вручную. Устаревший или неупорядоченный ответ `/api/status` не может перекрасить индикаторы: панель игнорирует ответы, пришедшие не по порядку, и снимки старше 15 минут.

## Почему пакет kas-core.ipk может отсутствовать

Если KAS установлен скриптами (штатный `curl | sh` bootstrap), пакет `kas-core.ipk` **необязателен**: Core работает из файлов, развёрнутых установщиком. Запись «Пакет kas-core не установлен» в разделе «Версии» в этом случае — не ошибка, и рядом появляется пояснение. Тревожиться нужно только при записи «Файлы KAS отличаются от состава пакета» (если пакет установлен) или при ошибках в Doctor.

## Почему версия Mihomo в opkg отличается от запущенного бинарника

Штатный `update-mihomo.sh` обновляет **только бинарник** и намеренно не переписывает базу opkg. Поэтому панель показывает три разных источника истины, и они могут расходиться:

- **runtime** — версия реально работающего процесса (например, `1.19.33`);
- **запись обновлятора KAS** — версия бинарника, подтверждённая `/opt/etc/keenetic-auto-setup-mihomo.state`;
- **база opkg** — версия пакетной записи Entware (например, `1.19.32-2`), которая может отставать от бинарника.

Это нормальное состояние, а не поломка. Обновление Mihomo из панели сравнивает runtime и запись обновлятора с опубликованным пакетом; «версия совпадает» не утверждается, когда записи расходятся.

## Как читать предупреждения Doctor

Нажмите «Запустить Doctor» в разделе «Диагностика». Итог: `OK` — ошибок и предупреждений нет; «предупреждений — N, ошибок — M» — есть находки. Известные предупреждения watchdog (формат отчёта `1.2.19`) показываются с отдельным заголовком и короткой безопасной подсказкой на русском и английском: повторные сбои в течение часа (проверьте WAN и прокси отдельно, причина не установлена), вмешательства watchdog за 24 часа (перезапуск сам по себе не доказывает проблему провайдера или Mihomo), историческая нестабильность (процесс может работать сейчас — смотрите, появляются ли новые предупреждения и успешные проверки после них). К каждой такой находке прилагается ссылка на [документацию watchdog](04-watchdog.md). Неизвестные находки остаются с оригинальным техническим текстом — без выдуманных советов. Полный отчёт доступен по стрелке «Подробности проверки», кнопка «Копировать отчёт» кладёт его в буфер обмена.

## Резервные копии настроек и YAML

- **Текущий YAML:** раздел «Конфигурация» → «Скачать текущий YAML» — файл с работающей конфигурацией. Сохраняйте его на доверенном ПК перед обновлениями и изменениями.
- **Настройки панели:** `/opt/etc/kas-control-center.settings.json` (порт, язык, режим доступа), файл пароля `/opt/etc/kas-control-center.password` — скопируйте их через SCP/SFTP при желании иметь полный снимок.
- **Восстановление:** YAML возвращается через штатный импортёр панели (раздел «Конфигурация»: вставка или загрузка файла) — тот же механизм с проверкой, резервной копией и откатом, что и при обычном импорте. Файлы настроек при обновлении панели сохраняются автоматически.

## Как сообщить об ошибке панели

Соберите перед сообщением:

1. Версию панели — под логотипом в sidebar (например, `KAS Web v0.1.0-beta.8`) и/или `opkg status kas-control-center`.
2. Вывод `sh /opt/etc/init.d/S98kas-control-center status` — в нём же фактический порт и адрес (`PANEL_ADDRESS`).
3. Отчёт Doctor — кнопка «Копировать отчёт»; **перед отправкой просмотрите его на личные данные**.
4. Что именно нажимали и что произошло: ожидаемое поведение, фактическое, текст ошибки из интерфейса.
5. Модель роутера и `opkg print-architecture` — какая из четырёх архитектур IPK установлена.

Сообщайте в issue репозитория или в Telegram-чат, где ведётся обсуждение. Не прикладывайте полный `config.yaml` и пароли — в отчёте Doctor секреты уже маскируются, но вручную просмотрите его перед отправкой.

## Удаление и восстановление

```sh
opkg remove kas-control-center
```

Удаляется только пакет Web-панели; KAS Core, Mihomo и MagiTrickle эта команда не удаляет. Настройки и YAML могут сохраниться. Уже применённый `exclude-filter` следует снять через Web **до удаления панели**, если его нужно отменить.

Если обновление завершилось ошибкой или панель не стартует, не выполняйте повторные установки параллельно. Через SSH проверьте `opkg status kas-control-center` и состояние службы; при `PANEL_RECOVERY_REQUIRED` воспользуйтесь документированным `/opt/bin/kas-control-center -recover-panel-update` после проверки отсутствия активной транзакции. Нет автоматического rollback. Если требуется переустановка, используйте **только проверенный IPK из текущего доступного релиза**; нельзя обещать восстановление старой удалённой beta-сборки.

Подробности сетевой защиты: [LAN.md](../web/control-center/LAN.md). Технический контракт самообновления: [PANEL_UPDATE.md](../web/control-center/PANEL_UPDATE.md).
