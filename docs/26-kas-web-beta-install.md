# KAS Control Center — установка и работа с тестовой WEB-панелью

**KAS Control Center** — отдельный, необязательный WEB-компонент для уже установленного [Keenetic Auto Setup](../README.md). Он не заменяет KAS Core и не переустанавливает Mihomo/MagiTrickle: позволяет просматривать состояние, запускать Doctor, импортировать YAML через штатный механизм KAS, управлять исключениями в подписках и вручную проверять обновления.

**Важно о версиях.** Тестовые выпуски Web часто сменяются, поэтому эта инструкция не содержит фиксированного номера беты и URL конкретного IPK. Актуальную установочную версию выбирают **по текущему опубликованному Web prerelease**, а не по прошлой инструкции. Архивные версии не поддерживаются в качестве способа новой установки.

## Требования и ограничения

- Keenetic/Netcraze с Entware, SSH и работающим KAS. Для штатного запуска Web необходим IPv4 на интерфейсе управления \`br0\`; название пользовательского сегмента в KeeneticOS значения не имеет.
- Проверить фактическую архитектуру Entware командой \`opkg print-architecture\`. Поддерживаемые варианты IPK: \`aarch64-3.10\`, \`armv7-3.2\`, \`mipsel-3.4\`, \`mips-3.4\`. Не выбирать архитектуру по приблизительному названию роутера.
- По умолчанию WEB слушает IPv4 интерфейса \`br0\`, TCP **8081**. Ранее сохранённый порт может отличаться.
- По умолчанию **нет пароля и TLS**. Привязка к \`br0\` сама по себе не запрещает доступ из других маршрутизируемых сетей. Не публикуйте Web через открытый WAN/port forwarding; ограничьте доступ доверенными управляющими сетями. Basic Auth по обычному HTTP не шифрует пароль.
- У Web нет автоматического отката IPK. Не используйте \`opkg --force-*\`, не выключайте питание во время установки и сохраняйте резервную копию настроек и YAML перед обновлением.

## Где взять актуальный IPK

1. Откройте [**GitHub Releases проекта**](https://github.com/saymer-alt/keenetic-auto-setup/releases).
2. Найдите **актуальный prerelease KAS Control Center / KAS WEB**, предназначенный для установки пользователями. **Не используйте GitHub «Latest»**: он относится к стабильному релизу **KAS Core**, а не к Web-панели.
3. На роутере выполните \`opkg print-architecture\`. Скачайте **один** соответствующий архитектуре IPK из выбранной публикации и файл \`SHA256SUMS\` **из той же публикации**.
4. Перенесите оба файла в отдельный каталог на роутере через SCP/SFTP либо скачайте их с доверенной машины. Не смешивайте файлы из разных релизов и не переименовывайте IPK.
5. Проверьте контрольную сумму до установки. \`SHA256SUMS\` может содержать относительные пути вида \`./имя-файла\`, поэтому нельзя полагаться на простой grep без учёта этого префикса.

Ниже пример **без привязки к версии и ABI**. Он предполагает, что в каталоге \`/tmp/kas-web-install\` находятся **ровно один выбранный IPK** и соответствующий \`SHA256SUMS\`:

\`\`\`sh
cd /tmp/kas-web-install || exit 1
set -- kas-control-center_*.ipk
[ "$#" -eq 1 ] && [ -f "$1" ] || { echo "Ожидается ровно один IPK"; exit 1; }
IPK=$1
awk -v name="$IPK" '
  $2 == name || $2 == "./" name { print; found++ }
  END { if (found != 1) exit 1 }
' SHA256SUMS > selected.sha256 &&
sha256sum -c selected.sha256 &&
opkg install "./$IPK"
\`\`\`

Проверка должна показать \`OK\`. Если файл не найден в \`SHA256SUMS\`, хеш не совпадает или архитектура не подходит — **не устанавливать**. \`sha256sum\` подтверждает соответствие скачанного пакета опубликованному списку, но не заменяет доверия к самому источнику.

После успешной установки:

\`\`\`sh
sh /opt/etc/init.d/S98kas-control-center start
sh /opt/etc/init.d/S98kas-control-center status
opkg status kas-control-center
\`\`\`

Запускать службу нужно явно после установки. Откройте \`http://<IPv4-адрес-br0>:8081/\` или ранее сохранённый порт. Убедитесь, что версия установленного IPK и работающей панели согласованы.

Если GitHub недоступен непосредственно с роутера, скачайте проверенные файлы на доверенном ПК и перенесите их SCP/SFTP. Не выполняйте случайные скрипты из альтернативных источников.

## Работа в WEB

- **Обзор** — версии KAS, панели, Mihomo и MagiTrickle, ручная проверка обновлений.
- **Подписки** — список серверов подписок и исключение выбранных узлов через штатный импортёр KAS; проверьте также возможность снять исключения.
- **Конфигурация** — вставка или загрузка полного YAML через штатный импортёр; перед изменением сделайте резервную копию.
- **Диагностика** — запуск Doctor и сводка результатов, включая предупреждения и ошибки.
- **Настройки** — язык, тема, порт и параметры доступа; конкретные элементы могут меняться в тестовых выпусках.

В карточке обновления Web выберите **Бета** или **Стабильный** и нажмите проверку версии. Смена канала сама ничего не устанавливает, обновление запускается только после подтверждения владельца. Наличие версии на канале зависит от того, опубликован ли соответствующий выпуск; GitHub «Latest» для выбора Web здесь не применяется.

После применения обновления убедитесь, что **установленная и работающая версии** совпадают, Web снова доступна, а YAML, Doctor, фильтры и доступ клиентов сохранились. На некоторых тестовых сборках открытая страница могла показывать старую версию до принудительного обновления браузера: это известное ограничение интерфейса, а не доказательство неудачной установки; проверяйте состояние службы отдельно.

## Удаление и восстановление

\`\`\`sh
opkg remove kas-control-center
\`\`\`

Удаляется только пакет Web-панели; KAS Core, Mihomo и MagiTrickle эта команда не удаляет. Настройки и YAML могут сохраниться. Уже применённый \`exclude-filter\` следует снять через Web **до удаления панели**, если его нужно отменить.

Если обновление завершилось ошибкой или панель не стартует, не выполняйте повторные установки параллельно. Через SSH проверьте \`opkg status kas-control-center\` и состояние службы; при \`PANEL_RECOVERY_REQUIRED\` воспользуйтесь документированным \`/opt/bin/kas-control-center -recover-panel-update\` после проверки отсутствия активной транзакции. Нет автоматического rollback. Если требуется переустановка, используйте **только проверенный IPK из текущего доступного релиза**; нельзя обещать восстановление старой удалённой beta-сборки.
