# Аудит локальной сетевой экспозиции KAS (read-only)

`kas-exposure-check.sh` — автономная read-only утилита ([#159](https://github.com/saymer-alt/keenetic-auto-setup/issues/159)) для локального анализа того, какие TCP-порты реально слушает роутер и как они привязаны. Инструмент ничего не меняет и не сканирует чужие сети — только собственные сокеты и собственная конфигурация.

## Контракт владельца (#159, 2026-11-01)

Mihomo Controller **без пароля и с неблокированным доступом** — принятое архитектурное решение KAS. Аудит фиксирует факты и никогда не считает нарушением: открытую привязку, `allow-lan`, отсутствие/пустоту/YAML-null `secret`, а также ответ HTTP 200 на неавторизованный запрос. Единственный `FAIL` — **противоречие** между заявленным (конфиг) и наблюдаемым (проба) состоянием аутентификации. Инструмент ничего не меняет в конфигурации и не требует установки пароля.

## Что проверяется

Инструмент разделяет три разных понятия:

1. **Сокет слушает адрес** — факт из `/proc/net/tcp` и `/proc/net/tcp6` (первичный источник — работает даже без `ss`/`netstat`): порт, семейство, класс привязки.
   - loopback (`127.0.0.1`, `::1`) → PASS;
   - wildcard (`0.0.0.0`, `::`) → INFO-факт «слушает все интерфейсы; внешняя доступность зависит от firewall/NAT и здесь НЕ проверена» — **не** подсчитывается как уязвимость;
   - конкретный адрес → UNKNOWN (доступность из других маршрутизируемых подсетей не исключается).
2. **Локальный запрос без авторизации получает ответ** — живая unauthenticated-проба `GET /version` (только с локальной точки зрения):
   - 200 → CONFIRMED (подтверждённый факт; при заявленном DISABLED — ожидаемое поведение по контракту);
   - 401/403 → REJECTED (авторизация включена);
   - недоступен/ошибка → UNKNOWN.
3. **API реально доступен извне** — **не проверяется** этим инструментом (firewall/NAT не парсится); в вердикте всегда указано `NOT verified`.

Дополнительно: **конфиг Mihomo** (`mixed-port`/`port`/`socks-port`, `allow-lan` — INFO «по дизайну», `bind-address`, `external-controller` — loopback → PASS, иначе INFO-факт по контракту); **заявленное состояние аутентификации** `Controller authentication: ENABLED / DISABLED / UNKNOWN` — по строке `secret:`: пустое значение, некавыченный `null`/`~` или пустые кавычки = DISABLED, любая непустая закавыченная строка (включая `"null"`) = ENABLED, несбалансированные кавычки = UNKNOWN; значение секрета намеренно никогда не выводится. **ProxyN-свидетельства** из `show running-config` — только отфильтрованные безопасные строки.

## Ключевые ограничения (прописаны в вердикте инструмента)

- **LISTENING ≠ доступность, локальный ответ ≠ внешний доступ.** Keenetic firewall/NAT правила не парсятся; про доступность из WAN инструмент мнения не даёт (NOT verified).
- Роутер может работать дома/на даче/в офисе/через VPN-подсети: привязка к `br0` не защищает клиентов других маршрутизируемых сетей — универсально «правильной» привязки не предполагается.
- UDP-слушатели не аудируются (семантика состояний в `/proc/net/udp` другая).
- Отсутствующие источники (нет конфига, нет ndmc, нет curl) дают `NOT TESTED`/`UNKNOWN`, а не догадки; при полном отсутствии socket-сведений итог — `inconclusive` (exit 3), а не «чисто».

## Запуск

```sh
sh kas-exposure-check.sh
```

Статусы: `PASS / FAIL / UNKNOWN / NOT TESTED / UNSUPPORTED`; `[INFO]`-строки — наблюдаемые факты. Коды возврата: `0` — факты собраны, заявленное и наблюдаемое состояние аутентификации согласуются; `1` — противоречие (например, `secret` задан, но API отвечает HTTP 200 без Authorization); `2` — ошибка использования; `3` — socket-сведений нет вообще (inconclusive).

Переменные-оверрайды (для тестов и нестандартных раскладок): `KAS_EXPOSURE_PROC_ROOT`, `KAS_EXPOSURE_CONFIG`, `KAS_EXPOSURE_CONTROLLER_URL`.

## Тесты

`tests/exposure-check-regression.py` — синтетические фикстуры `/proc` и конфигов: loopback-only, wildcard IPv4/IPv6 (факт, exit 0), конкретный адрес (включая little-endian порядок байт /proc), `allow-lan`/неблокированный `external-controller` как INFO, полная матрица `secret:` (пустая строка-значение, `null`, `~`, `""`, `''`, закавыченный `"null"`/`'null'`, значение с комментарием, `#` внутри кавычек, несбалансированная кавычка), согласованность заявленного и наблюдаемого (ENABLED+401, DISABLED+200 — exit 0; ENABLED+200, DISABLED+401 — противоречие, exit 1), недоступный Controller, 5xx, отсутствие всех источников (exit 3), ошибка использования. Проверяется, что значение секрета никогда не попадает в вывод.

## Ограничения достоверности

Регрессия доказывает логику на фикстурах; прогон на реальном железе (какие порты реально слушает Entware/Mihomo/панель, и как выглядит `show running-config` на 5.1.x) — за владельцем. Инструмент не проверяет Keenetic firewall и не даёт рекомендаций по изменению настроек.
