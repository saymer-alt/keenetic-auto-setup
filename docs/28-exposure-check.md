# Аудит локальной сетевой экспозиции KAS (read-only)

`kas-exposure-check.sh` — автономная read-only утилита ([#159](https://github.com/saymer-alt/keenetic-auto-setup/issues/159)) для локального анализа того, какие TCP-порты реально слушает роутер и как они привязаны. Инструмент ничего не меняет и не сканирует чужие сети — только собственные сокеты и собственная конфигурация.

## Что проверяется

- **Фактические listening-сокеты** из `/proc/net/tcp` и `/proc/net/tcp6` (первичный источник — работает даже без `ss`/`netstat`): порт, семейство, класс привязки.
  - loopback (`127.0.0.1`, `::1`) → PASS;
  - wildcard (`0.0.0.0`, `::`) → FAIL-находка «риск, зависит от firewall/NAT»;
  - конкретный адрес → UNKNOWN (доступность из других маршрутизируемых подсетей не исключается).
- **Конфиг Mihomo** (`/opt/etc/mihomo/config.yaml`): `mixed-port`/`port`/`socks-port`, `allow-lan`, `bind-address`, `external-controller` (loopback → PASS, иначе FAIL).
- **Controller secret**: классифицируется только **факт наличия** (SET / пустой / отсутствует); значение секрета намеренно никогда не выводится.
- **Живая проверка Controller**: unauthenticated `GET /version` — 401/403 = авторизация включена (PASS), 200 = API без пароля (FAIL).
- **ProxyN-свидетельства** из `show running-config` — только отфильтрованные безопасные строки; полный дамп конфигурации принципиально не печатается.

## Ключевые ограничения (прописаны в вердикте инструмента)

- **LISTENING ≠ доступность.** Keenetic firewall/NAT правила не парсятся; про доступность из WAN инструмент мнения не даёт (NOT TESTED).
- Роутер может работать дома/на даче/в офисе/через VPN-подсети: привязка к `br0` не защищает клиентов других маршрутизируемых сетей — универсально «правильной» привязки не предполагается.
- UDP-слушатели не аудируются (семантика состояний в `/proc/net/udp` другая) — честное ограничение v0.1.0.
- Отсутствующие источники (нет конфига, нет ndmc, нет curl) дают `NOT TESTED`/`UNKNOWN`, а не догадки; при полном отсутствии socket-сведений итог — `inconclusive` (exit 3), а не «чисто».

## Запуск

```sh
sh kas-exposure-check.sh
```

Статусы: `PASS / FAIL / UNKNOWN / NOT TESTED / UNSUPPORTED`. Коды возврата: `0` — небезопасных wildcard-привязок без аутентификации не найдено; `1` — есть рисковые находки; `2` — ошибка использования; `3` — socket-сведений нет вообще (inconclusive).

Переменные-оверрайды (для тестов и нестандартных раскладок): `KAS_EXPOSURE_PROC_ROOT`, `KAS_EXPOSURE_CONFIG`, `KAS_EXPOSURE_CONTROLLER_URL`.

## Тесты

`tests/exposure-check-regression.py` — синтетические фикстуры `/proc` и конфигов: loopback-only, wildcard IPv4/IPv6, конкретный адрес (включая little-endian порядок байт /proc), включённый `allow-lan`, непривязанный к loopback `external-controller`, секрет SET/пустой/отсутствующий, Controller 401/200/недоступен, отсутствие ndmc, отсутствие всех источников (exit 3), ошибка использования. Проверяется, что значение секрета никогда не попадает в вывод.

## Ограничения достоверности

Регрессия доказывает логику на фикстурах; прогон на реальном KN-1010 (какие порты реально слушает Entware/Mihomo/панель, и как выглядит `show running-config` на 5.1.x) — за владельцем. Инструмент не проверяет Keenetic firewall и не даёт рекомендаций по изменению настроек.
