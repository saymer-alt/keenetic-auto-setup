# 13 — безопасный импорт config.yaml

\`config-import.sh\` закрывает пользовательский шаг между генератором и работающим Mihomo без ручного редактирования в \`nano\`.

## Обычный сценарий

1. Создайте конфиг в [Mihomo Unified Generator](https://saymer-alt.github.io/link-generators/).
2. Скопируйте весь YAML.
3. На Keenetic выполните:

\`\`\`bash
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-auto-setup/stable/config-import.sh | sh
\`\`\`

4. Вставьте YAML и нажмите **Ctrl+D**.

Скрипт читает интерактивный ввод из \`/dev/tty\`, поэтому сценарий работает даже когда сам importer доставляется через \`curl | sh\`.

На время чтения importer включает `ICRNL` на `/dev/tty` (с сохранением и восстановлением исходных настроек терминала): некоторые SSH-сессии доставляют клавиатурный Enter как CR без перевода строки, и без этого `s` «проглатывался» при продолжавшемся эхе. CR также вырезается из каждой доставленной строки, поэтому CRLF-терминалы и вставленный CRLF-текст не ломают выбор `s`. Пустые строки перед первой строкой YAML игнорируются: они повторно показывают приглашение и не уводят в режим вставки.

## Что происходит

- candidate сначала пишется в отдельный файл рядом с \`config.yaml\`;
- до остановки сервиса проверяется проектный контракт \`mixed-port: 7890\`;
- importer не запускает второй Mihomo рядом с daemon: работающий сервис останавливается и остановка подтверждается;
- watchdog получает \`/tmp/mihomo.maintenance\` и не вмешивается в плановую паузу;
- candidate проверяется настоящим \`mihomo -t\`;
- текущий валидный \`config.yaml\` сохраняется как \`/opt/etc/mihomo/config.yaml.bak\` (см. «Восстановление» ниже);
- candidate становится canonical config одним same-filesystem \`mv\`;
- если сервис ранее работал, он запускается снова; проверяются процесс и порт 7890;
- при ошибке validation/start/port старый конфиг атомарно восстанавливается из \`.bak\`, а прежнее состояние сервиса возвращается.

В development importer берёт [общий lifecycle lock](19-lifecycle-lock.md) до stop/validation/commit и удерживает его до cleanup, включая восстановление сервиса. Отдельный updater-specific guard не нужен: updater использует тот же lock. Существующие legacy locks блокируют захват; параллельный запуск старых и новых копий инструментов не поддерживается.

## Импорт из файла

Для advanced-сценария:

\`\`\`bash
sh config-import.sh /tmp/config.yaml
\`\`\`

Файл проходит ту же транзакцию. Прямой overwrite canonical \`config.yaml\` importer не делает.

## Backup

После успешного импорта предыдущий конфиг остаётся здесь:

\`\`\`text
/opt/etc/mihomo/config.yaml.bak
\`\`\`

При следующем успешном импорте backup обновляется и содержит непосредственно предыдущую версию.

## Восстановление (issue #320)

Если текущий \`config.yaml\` отсутствует, пуст или не проходит \`mihomo -t\`, импорт не блокируется: KAS уже установлен (init-скрипт найден), поэтому importer выполняет **recovery-импорт** нового валидного YAML и печатает \`[WARN] recovery\`. Правила защиты:

- существующий хороший \`config.yaml.bak\` **никогда не перезаписывается** ни пустым или отсутствующим текущим файлом, ни невалидным непустым содержимым: такой текущий конфиг в backup не попадает вовсе;
- rollback при неуспешном импорте восстанавливает последний известный хороший конфиг из \`.bak\`; если \`.bak\` нет, importer честно сообщает об отсутствии точки восстановления;
- **повреждённый оригинал сохраняется побайтово**: если текущий \`config.yaml\` непустой, но невалидный, перед заменой его содержимое копируется в \`config.yaml.invalid\` (при занятом имени — \`config.yaml.invalid.1\`, \`.2\`, … до \`.99\`) с правами \`0600\` и проверкой целостности \`cmp -s\`. Публикация — **атомарное создание без перезаписи**: POSIX жёсткая ссылка \`ln\` без \`-f\` со stage-файла на той же файловой системе, поэтому существующее имя (обычный файл, символьная или «висячая» ссылка) перезаписать невозможно даже при гонке — \`ln\` на занятом имени завершается ошибкой, и берётся следующий суффикс. Это **не** рабочая резервная копия и **не** источник автоматического rollback — файл только для ручного анализа (там могут быть адреса серверов и параметры подписок). Существующие recovery-файлы никогда не перезаписываются, содержимое файла никогда не выводится. Если безопасное сохранение невозможно (нет места, отказ записи, недоступен \`cmp\`, файловая система не поддерживает жёсткие ссылки), импорт прерывается **до** замены: оригинал остаётся на месте, ничего не теряется;
- подсказка \`Run setup.sh first\` в этой ситуации больше не выводится: она относилась только к действительно неустановленному KAS (нет каталога или init-скрипта).

## Что importer не делает

- не генерирует YAML;
- не редактирует proxy links;
- не меняет Keenetic policies/DNS;
- не форматирует storage;
- не обновляет Mihomo binary;
- не делает URL-import.

Генератор отвечает за создание YAML, \`config-import.sh\` — только за безопасную установку готового конфига.

---

Безопасный importer использует общий CLI-контракт проекта: green = нормальный ход/OK, cyan = INFO, yellow = WARN, red = ERROR/FAIL. Подробности: [18 — цвета и статусы CLI](18-output-colors.md).
