# PREPARE #231 — ограниченная проверка экспериментального исправления

Это завершение уже начатого исправления поверх #227 → #215, **не новый контракт
обычного удаления**. По решению владельца в #225 точные rollback IPK, полный образ
USB, идеальная история Doctor и многоступенчатая приёмка не должны становиться
обязательными условиями обычной деактивации KAS. Дальнейшее расширение engine
остановлено. Текущий экспериментальный engine не превращён в простую удалялку.

Ниже только подготовка recovery-файлов по отдельному выбору владельца. Ничего
на KN-1010 агентом не выполнялось. Аппаратное удаление НЕ разрешено.

## Что исправлено

- Индексы: `/opt/var/opkg-lists`, прежний путь и `lists_dir ext PATH` в OPKG config.
- Наличие имени файла/URL в sources.v1 или изменяемого тега latest недостаточно.
  Нужен доверенный SHA256 плюс точные Package/Version/Architecture внутри IPK.
- `KAS_ROLLBACK_IPKS` — необязательный файл данных `SHA256|источник`, не shell.
  Источник: абсолютный локальный путь, basename рядом с manifest либо HTTPS URL.
  SHA утверждается независимо **до** загрузки, не вычисляется загрузчиком как
  «подтверждение» произвольного пакета. При SHA256 в доверенном OPKG-индексе
  допустима загрузка из соответствующего HTTPS feed. MD5-only индекс не заменяет SHA256.
- Проверяются структура Entware tar-IPK, control metadata и gzip payload; scripts
  preinst/postinst не выполняются. Учтён BusyBox tar с явным gzip-режимом.
- Новый cache строится приватно на внешнем EXT4 opt, публикуется полным, PREPARED
  записывается последним. Неполный cache — BLOCKED/3, без успешного prepare-маркера.
  Неполный маркер старой версии отзывается; существующий cache не уничтожается.
- Повтор с проверенным cache использует те же bytes без сети. Повреждённый старый
  cache сохраняется для разбора, операция BLOCKED; не заменять его автоматически.
  Journal уже существует — re-prepare запрещён. Прерванную транзакцию не пересоздавать.

## Если владелец всё же выбирает повторный PREPARE

Использовать весь набор скриптов из одного **reviewed SHA этого исправления**,
не перезаписывать один файл в старом архиве aef221f…. Путь KAS_DIR должен указывать
на этот согласованный набор; RUN — приватный каталог результатов на внешнем opt.
Не устанавливать/обновлять/удалять действующие пакеты ради формирования cache.

1. На ПК сохранить точные IPK. Для Mihomo 1.19.33-2 mipsel-3.4 владелец предоставил
   утверждённый SHA256 `331c1a48634f6272440d25c3033397f45f743cfa4065639c5bc08c119255123c`.
   Отдельно получить/утвердить SHA256 точного MagiTrickle 0.8.2-1 и проверить его
   control Architecture против `opkg status magitrickle` и `opkg print-architecture`.
   Не объявлять комплект проверенным только потому, что один Mihomo уже скачан.
2. Через существующий приватный канал скопировать оба IPK в `/opt/kas-ipk-import`
   на **внешнем** opt. Не использовать внутреннюю flash. Каталог 0700, файлы 0600.
3. Создать `/opt/kas-ipk-import/approved.sources`, owner тот же, что запускает
   PREPARE, права 0600. Пример для KN-пакета; второй hash обязательно заменить:

```text
331c1a48634f6272440d25c3033397f45f743cfa4065639c5bc08c119255123c|mihomo_1.19.33-2_mipsel-3.4.ipk
REPLACE_WITH_INDEPENDENTLY_APPROVED_MAGITRICKLE_SHA256|magitrickle_0.8.2-1_entware_mipsel-3.4_kn.ipk
```

Неподставленный/неверный hash даёт BLOCKED. Для HTTPS получения вместо basename
можно указать точный URL, сохранив тот же независимо утверждённый digest.
Название latest само по себе не устанавливает доверие к bytes или версии.

4. Только если нет прерванного journal: повторить snapshot/verify/gate из
   согласованного source-набора. При stale snapshot не редактировать YAML/ledger
   ради PASS; создать новый snapshot после разбора. При старом неполном cache
   сохранить старый SNAP для диагностики, использовать новый снимок.

```sh
sh "$KAS_DIR/uninstall-snapshot.sh" --create || exit 3
SNAP=YYYYMMDD-HHMMSS-PID  # точное имя нового снимка, не latest
sh "$KAS_DIR/uninstall-snapshot-verify.sh" "$SNAP" || exit 3
sh "$KAS_DIR/uninstall-transaction-gate.sh" --check "$SNAP" || exit 3
KAS_ROLLBACK_IPKS=/opt/kas-ipk-import/approved.sources \
  sh "$KAS_DIR/uninstall-transaction.sh" --prepare "$SNAP" > "$RUN/prepare.private" 2>&1
status=$?
printf 'PREPARE exit=%s\n' "$status"
test "$status" = 0 || exit 3
BACK=/opt/kas-uninstall-backups/$SNAP
(cd "$BACK/packages" && sha256sum -c MANIFEST) || exit 3
cat "$BACK/packages/wanted"
test -f "$BACK/transaction/prepare.v1" || exit 3
```

PASS означает **только полную проверенную подготовку**: два точных IPK, metadata,
checksums и prepare record. Он не даёт разрешения на удаление/аппаратный этап C.
Нужный MagiTrickle pin/реальный ABI пока не проверены этим агентом на устройстве.
Doctor WARN не очищались и не подменялись PASS; идеальная история Doctor не входит
в новый продуктовый контракт обычной деактивации.

Cache остаётся частью выбранного экспериментального SNAP, а не постоянным
хранилищем программы. Он нужен только пока владелец сохраняет этот эксперимент/
возможность его resume. После отказа от эксперимента нет продуктовой обязанности
хранить старые IPK на роутере; удаление конкретного диагностического SNAP —
осознанное решение владельца, не новый автоматический purge/retention manager.
Образ USB на ПК может остаться дополнительным независимым backup по выбору.
