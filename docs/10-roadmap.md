# Roadmap

Куда развивается проект.

Не обещания, а направления.

---

## 🧠 Общая идея

Проект развивается не ради "фич", а ради:

👉 стабильности  
👉 предсказуемости  
👉 минимизации ручной работы  

---

## 📍 Текущий статус

- ✔ Автоустановка (install.sh — единый путь: aarch64 / armv7 / mipsel / mips)
- ✔ Mihomo + проектный ProxyN (Proxy0 или первый свободный; чужой Proxy0 не трогается)
- ✔ bootstrap config.yaml (mixed-port: 7890, без зависимости от placeholder пакета)
- ✔ MagiTrickle
- ✔ Watchdog (самовосстановление)
- ✔ bypass_wa (VoIP стабилизация + авто-привязка политики к проектному ProxyN)
- ✔ S00ubifs (защита флешки)

✅ Выполнено вне этого плана (2026-09):

- bootstrap config.yaml (mixed-port 7890) — отвязка от placeholder пакета
- ProxyN-селекция проектного Proxy-интерфейса + защита чужого Proxy0
- авто-привязка bypass_wa к проектному ProxyN

## 🚧 Ближайшие задачи (Short-term)

---

### 1. Улучшение install.sh

- [x] ранняя проверка RAM до сетевых загрузок/изменений
- [x] resource-profile contract 20260921_1: 128MB-класс — только внешний /opt + внешний storage-backed swap >=384 МБ (project-specific floor; zRAM не входит), иначе installer FAIL; 256 МБ — нужен один backend: zRAM или внешний storage-backed swap; 512 МБ+ swap/zRAM не требуют; совместный zRAM + disk/file swap получает WARN по vendor guidance; updater существующих legacy-инсталляций profile-нарушения не блокирует
- [x] явная диагностика критических ошибок: Proxy client, полный read-back проектного ProxyN, обязательный bootstrap, DNS interception и финальный self-check
- [x] проверка обязательного DNS-контракта: `dns-proxy intercept enable` применяется и немедленно читается обратно
- [ ] необязательная диагностика здоровья upstream DNS — только если появится воспроизводимый практический кейс; не делать её hard gate установки

---

### 2. Дальнейшее развитие Watchdog

- [x] защита от ложных рестартов (lock-файл, cooldown 300 с, whitelist-fallback
      WAN-проверки, jitter — уже в текущей версии watchdog)
- [x] уменьшить шум healthy-логов: проверки остаются каждые 5 минут, `[OK]` heartbeat — не чаще раза в 20 минут; WARN/restart/rate-limit, первый recovery `[OK]` и смена WAN-пути `primary ↔ whitelist` пишутся сразу
- [ ] добавить уровень логирования
- [ ] расширить проверку здоровья upstream за пределы текущего GET через SOCKS5h

---

### 3. Обновление и автообновление компонентов

- [x] обновление Mihomo без переустановки (`update-mihomo.sh`)
- [x] обновление watchdog (`update-watchdog.sh`)
- [x] безопасные ручные update-скрипты (валидация, maintenance coordination, rollback)
- [ ] **Следующий этап после v1.4.0:** отдельный opt-in `install-auto-update.sh`; основной `install.sh` автообновление не включает
- [ ] `install-auto-update.sh` устанавливает локальный auto-updater и суточный cron с jitter; пользователь включает этот механизм отдельным осознанным запуском
- [ ] auto-updater читает manifest из production/`stable` и обновляется только при двух разрешениях: локальный opt-in + GitHub-флаг, например `enabled=1` и `version=1.4.2`
- [ ] пользовательские `config.yaml`, MagiTrickle-конфиги и HWID-зависимые настройки автообновление не трогает

---

## 🔧 Среднесрочные задачи (Mid-term)

---

### 5. Централизованная конфигурация (опционально, позже)

Идея:

👉 один источник `config.yaml` для нескольких роутеров без ручного копирования.

Это не short-term задача. Сначала нужны стабильный release-channel и безопасное
автообновление компонентов; централизованную доставку пользовательских конфигов
имеет смысл проектировать отдельно, только если появится практическая потребность.

---

### 6. Мониторинг (опционально)

- [ ] простой health-check endpoint, если он реально понадобится
- [ ] внешний статус/сбор логов — не дублировать отдельными механизмами, если задачу уже решает внешний агент мониторинга

---

### 7. Улучшение диагностики

- [x] единая read-only команда диагностики — `mihomo-doctor.sh`
- [x] вывод состояния системы, Mihomo, ProxyN, DNS, MagiTrickle, watchdog, истории и маршрутизации
- [x] финальный self-check в `install.sh`
- [x] маленький постоянный contract smoke test — `tests/contracts.sh`
- [ ] расширять Doctor только по новым воспроизводимым полевым кейсам; не превращать его в repair tool

## 📌 Как принимать решения

Перед добавлением фичи:

1. Это реально нужно?
2. Это усложняет систему?
3. Это увеличивает риск поломки?

Если ответ "да" на 2 и 3:

👉 не добавлять
