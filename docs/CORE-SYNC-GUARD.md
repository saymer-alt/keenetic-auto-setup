# Core Sync Guard — read-only контроль main/stable

Цель: замечать новые изменения общего runtime KAS Core, включая изменения
корневых shell-скриптов при разработке KAS Web. Не добиваться равенства
main и stable любой ценой. Связано с policy issue #369.

## Что проверяет

- Все файлы *.sh **в корне** репозитория, найденные в объединении Git-деревьев
  кандидата main и stable. Новые и удалённые корневые скрипты тоже видны.
- Совпадение *полных Git blob SHA* (не сравнивает SHA веток/историю коммитов).
- config/core-sync-baseline.json хранит **точечные** подтверждения известных
  отклонений: путь, SHA обеих копий (или null для отсутствующей), причина.
- Любое изменение хотя бы одного SHA снимает прежнее подтверждение и переводит
  файл из ACKNOWLEDGED в REVIEW. Никаких вечных исключений по пути.

Результаты:
- SYNC: побайтовое совпадение;
- ACKNOWLEDGED: известное расхождение, совпадающее с пинованной парой;
- REVIEW: новое / изменённое / необъяснённое расхождение.

REVIEW — **не признак дефекта** и не разрешение на backport.
main и stable различаются по дизайну. Обновлять baseline допускается только
после отдельной проверки отличий и объяснения, почему различие принято.

## Когда запускается

- PR к main, затрагивающий корневые *.sh или собственные файлы Guard.
  Сравнивается **голова PR**, а не просто текущая main.
- Любой push в main;
- ежедневно в 07:17 UTC по GitHub schedule;
- вручную через workflow_dispatch.

Workflow: .github/workflows/core-sync-guard.yml (permissions: contents: read).
Не работает на роутере, не изменяет Git refs, не коммитит и не добавляет
метки или комментарии в PR. Отчёт виден в Job summary, в логах с предупреждениями
и в JSON-артефакте. Расхождения не ломают CI; ошибки самого
чекера/невалидные refs, наоборот, обозначают неисправный контроль.

Пример локальной проверки в клоне с обеими remote refs:

    git fetch origin main stable
    python3 tests/core-sync-guard-regression.py
    python3 scripts/core-sync-check.py \
      --main-ref origin/main --stable-ref origin/stable \
      --config config/core-sync-baseline.json \
      --json-out /tmp/core-sync-report.json

## Границы v1

Контроль включает именно корневые оболочечные скрипты Core.
Глубокие интеграции, web/, packaging/core/, PowerShell/Go/Python,
CI-файлы и документация **не сравниваются**. Для них нужны отдельные
контракты и ревью, без смешивания с production drift.

Workflow намеренно остаётся только в main: нет никаких изменений
stable, релизных тегов, QEMU-gates или текущего цикла beta.6/v1.8.7.
Следующий этап — обсудить после реального использования, какие дополнительные
production-файлы стоит включить в охват, без автоматического переноса кода.
