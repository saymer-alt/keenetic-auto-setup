# KAS Core v1.8.9 — надёжная установка и загрузка IPK

**Дата:** 14 ноября 2026 года. **Канал:** Core stable после утверждения выпуска. Отдельная KAS Web beta.9 в этот Core-релиз не входит.

## Главное
- Увеличено окно скачивания больших Mihomo IPK с 180 до **1800 секунд**. При устойчивой скорости ниже 1 КиБ/с в течение 120 секунд curl прерывает попытку как зависшую; три попытки и очистка неполных файлов сохранены.
- Реальный прогресс каждой попытки отображается в интерактивном терминале.
- На первоначальной установке доступен дополнительный проверяемый путь через GitHub Release Asset API до возврата к Entware feed.

## Изменено
- `install.sh`: bounded HTTPS-only загрузки MagiTrickle (включая запрет редиректа HTTPS→HTTP), ограниченное ожидание wget, проверка размера/SHA256 при доступности дайджеста.
- `setup.sh`: ограничение времени первичной загрузки wget при наличии `timeout`.
- `update-mihomo.sh`: новый бюджет загрузки большого IPK; **обновляет бинарник Mihomo, а не весь Core**.
- Добавлены read-only инструменты `kas-download-check.sh`, `kas-entware-preflight.sh` и `uninstall.sh --check/--plan`. `kas-network-doctor.sh` и наблюдатель выбора прокси уточнены.
- `kas-universal-install.sh` доступен с режимами `check|all|core|web|doctor`, но **пока закреплён за Core v1.8.8 и Web beta.8**; для установки 1.8.9 до отдельного обновления пинов используйте штатный `bootstrap.sh`/ `install.sh` из `stable`.

## Безопасность
- Сохранены KAS-SAFETY-001 (нет одновременного zRAM и внешнего SWAP), один экземпляр Mihomo, сохранность пользовательского YAML, отказ при непроверенных зависимостях и механизмы остановки/отката файлового обновления.
- `uninstall-packages.sh` остаётся рабочим **частичным** деинсталлятором (останавливает демоны и удаляет пакеты через opkg); полное удаление KeeneticOS-настроек намеренно отсутствует. Форматирование выделенного Entware-накопителя — отдельное ручное действие владельца.
- `kas-update.sh --apply` управляет только watchdog/cron-парой, не всеми компонентами.

## Совместимость и ограничения
- `wget` на тестовом KN-1010 при HTTPS-проверке завершился с SIGSEGV (код 139); рабочими оказались `curl` и GitHub Contents API. Без `timeout` wall-clock ограничение для wget имеет оговорённые ограничения.
- Doctor предупреждает об отсутствии активных MagiTrickle `MT_*` mangle-цепочек при нуле настроенных групп. Функциональное применение правил MT не заявляется проверенным.
- На KN-1010 проверена успешная вставка полного YAML; интерактивный пропуск `s` на этой установке не тестировался. После перезагрузки конфигурация присутствует, но отдельная контрольная сумма непосредственно перед reboot не была зафиксирована.
- Докачка HTTP Range ещё не реализована (перенесена в Core 1.8.10). Возможны расхождения OPKG-базы и реально исполняемого Mihomo после `opkg upgrade`; не отключайте digest-проверки и не заменяйте обновлятор на массовое обновление OPKG.

## Установка и откат
- Новая установка после публикации: скачать `bootstrap.sh` из `stable` по HTTPS, проверить его и запустить штатным способом. `stable` не использовать для отката.
- Для возврата на 1.8.8 закреплённый коммит: `c80e47c7050a31f70f65312dcd8999bfb13c9bef`; повторная установка старой версии не является полным транзакционным откатом пакетов и настроек.
