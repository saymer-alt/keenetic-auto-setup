# KAS Core v1.8.10 — защищённая доставка скриптов и MagiTrickle `_kn`

**Дата:** 21 ноября 2026 года. **Канал:** Core stable после утверждения выпуска. Отдельная KAS Web beta.9 в этот Core-релиз не входит.

## Главное
- **Доставка скриптов с проверкой целостности.** Установщик проверяет SHA256 всех трёх поставляемых извне скриптов (`S00ubifs`, `020-bypass_wa.sh`, `mihomo-watchdog.sh`) по пинам ревизии `${KEENETIC_AUTO_SETUP_REF:-stable}`: staged-загрузка, повторная проверка дайджеста, атомарный `mv`. Неверный дайджест = отказ конкретного шага (fail-closed), прежний файл не затрагивается.
- **Отказ доставки bypass-hook прерывает установку** (поведенческое изменение; раньше — предупреждение и продолжение без hook). Установка без обязательного hook больше не считается успешной. Уже установленный hook при сбое не удаляется, повторный запуск установщика безопасен.
- **Повторная доставка bypass-hook без загрузки.** Уже установленный `020-bypass_wa.sh` переиспользуется локально без второго скачивания, только если это обычный исполняемый файл в доверенном каталоге и его SHA256 точно совпадает с пином ревизии установщика; любое отклонение (файл отсутствует, symlink, не исполняем, другой дайджест, нет `sha256sum`) уходит в прежнюю верифицированную цепочку загрузки и остаётся fail-closed. Переиспользование без пина невозможно.
- **Зеркало GitLab как последний резерв доставки скриптов** (issue #232): `bootstrap.sh`/`setup.sh` после всех GitHub-транспортов пробуют верифицированное зеркало (только чтение) с контрактом конца файла `# KAS_EOF_V1` и минимальным размером; `update-mihomo.sh` и `mihomo-doctor.sh` доставляются через тот же staged-контракт (`bootstrap.sh --script`). Включён fail-closed инструмент публикации GitLab-зеркала Mihomo IPK (`saymer-alt/entware-go`) с независимой проверкой lock-манифестов (1.19.34-2 / 1.19.34-3).
- **MagiTrickle**: перенос официального `_kn` GitHub/GitLab fallback (#215, issue #505) и исправление свежей установки Entware: парная `_kn`-архитектура выводится из единственной whitelisted plain-архитектуры и регистрируется один раз в KAS-owned фрагменте `/opt/etc/opkg/kas-mt-arch.conf` (приоритет plain+1, запись в ownership ledger; `opkg.conf` и `magitrickle.conf` не изменяются). **Generic MagiTrickle не мигрирует автоматически** — warn и пропуск MT-секции, установка продолжается; **ARMv7 пропускает MT** (upstream не публикует `_kn` для armv7, generic IPK запрещены). Deинсталляция несёт фрагмент: валидация журнала, `--cleanup` только после успешных `opkg remove` (инвариант «пакет до фрагмента»).
- **Детекция рассинхронизации curl/libcurl** (#254): read-only preflight/doctor выявляет несогласованные OPKG-записи curl/libcurl; Web-инсталлятор отказывается работать (fail-closed) на непригодном curl/libcurl runtime — включая ранее не разрешавшиеся символы и внятный отчёт о перекосе версий.
- **S28-first имена сервисов.** Свежие пакеты entware-go (1.19.34-3+) ставят сервис `S28mihomo`; на старых установках сохраняется `S99mihomo`. Документация и команды README обновлены; доставка `mihomo-doctor.sh`/`update-mihomo.sh` из README переведена на `bootstrap.sh --script`. Doctor объясняет, что внешний `opkg upgrade` применяет устаревшую feed-запись и откатывает бинарник на версию из фида (#58/#320, только диагностика — автоматические holds не ставятся).

## Безопасность
- Сохранены KAS-SAFETY-001 (нет одновременного zRAM и внешнего SWAP), один экземпляр Mihomo, сохранность пользовательского YAML, fail-closed поведение установщика.
- **Не вошло (осознанно):** RCI-токенизация (#258/#259) — отложена на 1.8.11; Web beta.10/beta.11 — отдельный релизный трек; экспериментальная упаковка Core IPK — отдельная работа.
- Пины пересчитаны по фактическим байтам public stable на 21.11.2026 — MATCH (×3).

## Known Issues
1. **Mihomo 1.19.34 падает при системном времени 1970 года** (холодная загрузка до синхронизации NTP). Upstream-дефект; в дереве обхода нет. Решение владельца: релиз не задерживается исключительно из-за этого сценария. Cold boot **не объявляется полностью безопасным** до upstream-фикса или обхода (кандидат — ожидание времени в S28-ините) в 1.8.11.
2. `update-watchdog.sh` валидирует удалённый кандидат маркером + `sh -n` без SHA256-пина (pre-existing поведение 1.8.9; решение о переносе пининга — отдельная задача).
3. GitLab-зеркало KAS не публикует IPK Mihomo (#481) — IPK качаются только с GitHub (entware-go); зеркало служит резервом доставки скриптов, а не пакетов.

## Совместимость и ограничения
- Повторный запуск `bootstrap.sh` → `setup.sh` → `install.sh` идемпотентен: существующий бинарник Mihomo не переустанавливается, конфиг пользователя не изменяется, ProxyN не перезапускается; hook, совпадающий с пином ревизии, переиспользуется без сети.
- На устройстве с уже установленным generic MagiTrickle повторный запуск не мигрирует его на `_kn` (warn + пропуск MT-секции); на ARMv7 MT-секция пропускается; `_kn`-фрагмент регистрируется только один раз.
- `kas-universal-install.sh` остаётся закреплённым за Core v1.8.9 / Web beta.9 до отдельного обновления пинов после публикации (свойство отката).
- Полное автоматическое удаление вне скоупа; `uninstall-packages.sh` — проверенный частичный деинсталлятор.
- Публикация тега `v1.8.10` на GitLab-зеркале — сразу после GitHub (зеркальный fallback проверяет контракт `# KAS_EOF_V1` и отказывает на устаревшем ref, а не отдаёт старый код).

## Установка и откат
- Новая установка и обновление 1.8.9 → 1.8.10: штатный `bootstrap.sh` из `stable` по HTTPS (команда в README); обновление бинарника Mihomo — отдельно и транзакционно через `bootstrap.sh --script update-mihomo.sh`.
- Откат репозитория: revert merge-коммита 1.8.10 на `stable`; закреплённый коммит 1.8.9 — `44c6b901709343a30e2503949037c7e66dd6e831`; повторная установка старой версии не является полным транзакционным откатом пакетов и настроек.
- На устройстве: `uninstall.sh` (сначала read-only preflight), затем `uninstall-packages.sh`; журнал владения фиксирует созданные установщиком артефакты.

**Исходный проверенный код кандидата:** `c1194b8abf203180f754b2d48572251801ac26b9` (выборочный перенос в `stable`; состав `stable` должен выборочно совпадать с ним по релизным Core-файлам без Web, RCI-токенизации и экспериментальной упаковки Core IPK).
