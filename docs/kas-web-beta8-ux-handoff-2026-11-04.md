## 2. Цветовая модель: одна палитра, четыре смысла

UI должна отличать состояния:

1. **Зелёный:** подтверждённый `running` из свежего успешного backend runtime observation; подпись «Процесс запущен». Сопроводить нейтральной поясняющей строкой: запущенный процесс **не гарантирует доступность сети, VPN, DNS, целевых сайтов**.
2. **Красный:** только подтверждённый `stopped` («Процесс не запущен») и отдельное проверенное `absent` («Не установлен»). Не красить отсутствие необязательного пакета `kas-core` как отказ всей системы.
3. **Жёлтый/янтарный:** `unknown`, временный сбой/неполное наблюдение; нет доказательств ни RUNNING, ни STOPPED.
4. **Серый:** ещё нет данных, данные устарели, запрос к API не завершился. Не оставлять зелёный stale статус при ошибке refresh; не смешивать timestamp Doctor с runtime sample.

Точное решение по цвету `absent` — отдельная явно текстовая семантика «не установлен», вместо универсального красного «не работает». Красный для критичного сервисного отсутствия допустим только при подтверждённой обязательности данного компонента в текущем профиле.

**Реализация:** безопасный DOM `textContent`, `data-state` или классы на конкретном элементе (не на всей карточке); CSS design tokens для light/dark/system, хорошие контрасты WCAG AA, значок + текст для нарушений цветовосприятия. Не использовать мигание/постоянные анимации, сохранить reduced-motion. Никакой постоянной фоновой диагностики или новых внешних запросов.

**Test matrix:** `running`, `stopped`, `absent`, `unknown`, отсутствие `runtime`, HTTP error/timeout, invalid data, safe HTML text, смена языка и темы, узкий экран 320/360px; проверить, что `/api/status` лишь читается и ничего не перезапускает.

## 3. Doctor: полезно по-русски, но не выдумывать диагноз

**Фактический beta.7 defect:** `web/control-center/web/doctor-report.js`, `render()`, section `8b` → категория `watchdog`, которая в `labels.ru.watchdog` переводится «Расписание проверки watchdog». Три различных WARN после реального Doctor 1.2.19 стали тремя одинаковыми строками. Их `finding.evidence` хранится, виден в раскрываемом `<details>`.

Для beta.8:
- Развести **«Расписание watchdog»** (карточка факта установки cron) и **«История и стабильность watchdog»** (категория findings section 8b).
- Для трёх точно известных шаблонов `mihomo-doctor.sh` и fixture NC-4210 предложить отдельные **короткие заголовки**, без неоднозначности:
  - `Repeated failures: 4 problem events within the same clock hour` → «Повторные сбои за один час». Совет: «Сравните новые события в журнале watchdog; если повторятся, отдельно проверьте WAN и доступность прокси».
  - `Watchdog interventions in the last 24h: 11 ...` → «Частые перезапуски за последние сутки». Совет: «Изучите интервалы и типы отказов; не делайте вывод о причине без сетевой диагностики».
  - `Historical stability: WARN` → «Предупреждение об истории стабильности». Совет: «Сейчас процесс может работать; проверьте, появляются ли новые сбои».
- Точные значения `4` и `11` не hardcode в UI. Парсить только валидированные числа из версионированного формата, или использовать короткие общие заголовки и точные evidence внутри.
- Не приписывать автоматически проблему Mihomo, ISP, DPI, DNS или VPN конкретной причине.
- Короткая подсказка, при наличии — ссылка в документацию проекта, **без автоматического открытия**, сторонней загрузки или выделения произвольного текста как HTML.
- Нераспознанное предупреждение остаётся `WARN · история watchdog` + точный исходный очищенный evidence; никаких неизвестных «рецептов». Полный отчёт и копирование прежние.
- Договорённости #274 и #393 сохранить: разбор только завершённого согласованного итогового отчёта, bounded parser, XSS/redaction safe.

## 4. Ручной перезапуск Mihomo — исследование, не функция по умолчанию

Отзыв внешнего тестировщика: «Кнопка перезапуска Mihomo не нужна?».

Прежде чем создавать actuator, документировать:
- Реальный потребитель: для чего нужен ручной restart, если уже есть watchdog, конфиг-импортёр, и управляющий Controller.
- Сравнение `/opt/etc/init.d/S99mihomo restart` против controller reload: restart процесса не тождественен reload конфигурации, restart обрывает текущие соединения.
- Lock/fencing: исключить гонки с `config-import.sh`, update-mihomo, watchdog, panel self-update и очередями; не запускать **второй** Mihomo.
- Права, CSRF/Origin/Host, подтверждение, anti-double-click, timeout, операция изолирована, подтверждение фактического нового PID/runtime и границы успеха.
- Что делать при failed restart (не обещать rollback или восстановление Интернет-доступа без доказательств).

**Исход:** отдельный RFC/issue и owner GO на добавление mutating Web endpoint; в базовой beta.8 не реализовывать.
