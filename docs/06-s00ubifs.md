# S00ubifs — защита флешки и RAM-режим

Почему используется tmpfs и где это НЕ нужно включать.

---

## Задача

Снизить износ флешки (/opt) за счёт переноса временных данных в RAM.

---

## Проблема

Entware активно пишет:
- логи (mihomo, watchdog)
- PID-файлы
- временные файлы
- кэши

При постоянной работе:

👉 флешка умирает через 6–12 месяцев  
👉 особенно на 20+ роутерах  

---

## Решение

Перенести volatile-данные в RAM:

```

/opt/tmp
/opt/var/log
/opt/var/run

```

через tmpfs

---

## Как это работает

Сервис:

```

/opt/etc/init.d/S00ubifs

````

Запускается раньше всех (`S00`).

---

### При старте

Размеры подбираются автоматически по свободной RAM (профили):

| Профиль | Свободная RAM | /opt/tmp | /opt/var/log | /opt/var/run |
| ------- | ------------- | -------- | ------------ | ------------ |
| low     | < 40 МБ       | 5M       | 2M           | 512k         |
| medium  | < 80 МБ       | 10M      | 5M           | 1M           |
| high    | ≥ 80 МБ       | 20M      | 10M          | 1M           |

```bash
mount -t tmpfs -o size=$SIZE,mode=$MODE,noatime,nosuid,nodev tmpfs "$d"
````

---

### Что остаётся на диске

* /opt/bin (пакеты)
* /opt/etc (конфиги)
* config.yaml
* crontab

---

### Что уходит в RAM

* логи
* временные файлы
* сокеты
* PID

---

## Почему это важно

Без этого:

* постоянная запись на флешку
* деградация скорости
* eventual failure (смерть накопителя)

---

## Главный момент: ОГРАНИЧЕНИЕ ПО RAM

👉 **Поддерживаемый профиль: 256 МБ RAM и больше** (512 МБ+ — самый запасной). Active swap не обязателен: на 256 МБ он даёт дополнительный запас памяти, на 512 МБ+ — по желанию.

128 МБ-класс допускается **только как best-effort/experimental и только с активным swap**: минимум **384 МБ** (512 МБ предпочтительно; в расчёт идёт `SwapTotal` из `/proc/meminfo` — подойдёт и swap-раздел). Без достаточного активного swap установщик останавливается на раннем preflight, до скачиваний и изменений; сам проект swap никогда не создаёт и не меняет. Режим `disk` предпочтительнее `ram`.

---

## ⚠️ 128 МБ: BEST-EFFORT (реальный опыт)

### 128 МБ устройства

Примеры:

* Keenetic Extra (MT7628)
* Keenetic Viva старый (MT7621, 128MB)

---

### Что происходит

* RAM занята почти полностью (~120/128)
* не стартуют штатные сервисы Keenetic
* нестабильная работа
* random падения

👉 система начинает "сыпаться"

---

### Вывод

Установка на 128MB **разрешена только с активным swap от 384 МБ** (512 МБ предпочтительно), и стабильность не гарантируется даже со swap. Реальный опыт показал, что сочетание малого запаса RAM и tmpfs способно дестабилизировать Keenetic. Поэтому сначала предпочтителен `disk`; `ram` — только осознанный эксперимент с наблюдением за памятью.

---

## ✔️ Рекомендуется

| RAM     | Статус                  |
| ------- | ----------------------- |
| 128 MB  | ⚠️ best-effort / experimental, только с активным swap >= 384 МБ (512 предпочтительно) |
| 256 MB  | ✅ поддерживается (swap опционален) |
| 512 MB  | ✅ нормально (swap опционален) |
| 1024 MB | ✅ идеально              |

---

## Почему именно такие размеры tmpfs

Значения ниже — профиль high (≥ 80 МБ свободной RAM); при меньшем объёме скрипт уменьшает размеры сам (см. выше).

| Директория   | Размер | Почему          |
| ------------ | ------ | --------------- |
| /opt/tmp     | 20M    | временные файлы |
| /opt/var/log | 10M    | логи            |
| /opt/var/run | 1M     | PID и сокеты    |

## Проверка

### Смонтировано ли

```bash
mount | grep tmpfs
```

---

### Использование RAM

```bash
df -h /opt/var
```

---

### Статус сервиса

```bash
/opt/etc/init.d/S00ubifs status
```

---

## Что теряется при reboot

Это важно понимать:

* логи watchdog
* логи mihomo
* временные файлы

👉 это НОРМАЛЬНО

---

## Когда использовать disk режим

Если:

* мало RAM
* нужен persistent лог
* нестабильность системы

👉 отключить tmpfs

---

## Почему не весь /opt в RAM

Потому что:

* пакеты должны сохраняться
* конфиги должны сохраняться
* иначе после reboot всё исчезнет

---

## Почему именно init.d (S00)

* запускается раньше всех сервисов
* гарантирует, что:

  * cron
  * mihomo
  * watchdog

уже работают с tmpfs

---

## Частые проблемы

### Не смонтировалось

Причины:

* мало RAM
* ошибка mount

Проверка:

```bash
dmesg | grep tmpfs
```

---

### Система стала нестабильной

👉 почти всегда нехватка RAM

Решение:

* отключить S00ubifs
* или перейти на роутер с 256+ МБ

---

## Итог

S00ubifs:

✔ защищает флешку
✔ снижает запись
✔ повышает ресурс

НО:

❗ требует достаточной RAM
❗ на 128 МБ-классе работает только best-effort (обязательно активный swap >= 384 МБ) и может быть нестабилен

---

## Коротко

👉 256+ МБ → `ram` штатно
👉 128 МБ → сначала активный swap >= 384 МБ (512 предпочтительно); предпочтительно `disk`; `ram` только как best-effort с контролем памяти
