# KAS — безопасное удаление: проверка состояния

**Сейчас доступен только `--check`. Автоматическое удаление пока НЕ реализовано.**
[Задача #179](https://github.com/saymer-alt/keenetic-auto-setup/issues/179).

## Почему недостаточно opkg remove

KAS может настраивать ProxyN, policy `bypass_wa`, правила Netfilter,
`dns-proxy intercept`, cron/watchdog, а также устанавливать Mihomo и MagiTrickle.
Старые версии не сохраняли полноценные данные о том, какие объекты созданные KAS,
а какие использовались раньше. Удаление по имени вроде `Proxy0` опасно.

Нельзя считать `opkg remove mihomo magitrickle` безопасным полным удалением.
Не удаляйте целиком `/opt/etc/mihomo`, чужие политики, Entware, swap/zRAM,
глобальный DNS или общий MagiTrickle.

## Журнал для новых установок

Новый `install.sh` на отдельной ветке реализации создаёт приватный журнал
`/opt/etc/keenetic-auto-setup/ownership.v1` (**KAS_OWNERSHIP_V1**).
Запись выполняется атомарно с правами `0600`, после успешного создания/включения объекта.
На повторном запуске журнал не объявляет уже существовавшие объекты собственностью KAS.

В журнал могут попадать только подтверждённые новые объекты: конкретный `ProxyN`,
новая политика `bypass_wa`, включение ранее выключенного DNS-перехвата,
ранее отсутствовавшие пакеты `mihomo`/`magitrickle`,
`magitrickle.conf`, Netfilter-хук, watchdog и `S00ubifs`.
Чужие/переиспользованные элементы туда не записываются.

**Журнал — необходимое, но недостаточное условие удаления:** ресурс мог стать общим
уже после установки. Перед фактическим удалением нужно проверить актуальную
конфигурацию и зависимости. Запись о включении DNS-перехвата, например,
сама по себе **не разрешает его выключить**.

На старых установках без журнала `--remove` и `--purge` запрещены.
Универсального `--force` не будет: так можно удалить чужой ProxyN или политику.

### Особенность MagiTrickle

У MagiTrickle существует штатная процедура удаления: остановить
`S99magitrickle`, выполнить `opkg remove magitrickle`, при желании очистить
`/opt/var/lib/magitrickle` и удалить репозиторий Entware.
В KAS это **разные решения**:

- остановка сервиса и удаление пакета — только при подтверждённом создании
  пакета этим KAS и отсутствии признаков совместного использования;
- содержимое `/opt/var/lib/magitrickle` — пользовательские настройки,
  по умолчанию **сохраняется**; очистка допускается лишь по отдельному
  подтверждению в будущем `--purge` и после резервной копии;
- `/opt/etc/opkg/magitrickle.conf` удаляется только если он создан KAS
  и после проверки, что репозиторий больше никому не требуется;
- `curl`, `jq`, `nano`, `cron`, базовый Entware и компоненты KeeneticOS
  деинсталлятор не удаляет.

## Проверка на тестовом KN-1010

После публикации в `main` скачать диагностический скрипт в отдельный временный файл и запустить **только** `--check`:

```sh
curl -fSsL -o /tmp/kas-uninstall.sh https://raw.githubusercontent.com/saymer-alt/keenetic-auto-setup/main/uninstall.sh && sh -n /tmp/kas-uninstall.sh && sh /tmp/kas-uninstall.sh --check
```

Пришли вывод для проверки признаков `SHARED_OR_FOREIGN` и `UNKNOWN`. **Пока не выполнять** `opkg remove`, `rm -rf`, `--remove` и `--purge` и не стирать Entware: иначе нельзя будет проверить настоящий деинсталлятор на исходном состоянии. В KN-1010 из предыдущих логов известны переиспользованный Proxy1 и чужой Proxy0, поэтому `чистая Entware` не равна `пустому KeeneticOS`.

## Только просмотр

Скачанный отдельно `uninstall.sh` можно запустить в режиме:

~~~sh
sh uninstall.sh --check
~~~

Аудитор читает файлы Entware, `opkg list-installed` и только информационные
`ndmc -c 'show running-config'`, `ndmc -c 'show ip policy'` и
`iptables -t mangle -S _CUST_BYPASS_WA_`. Он не останавливает службы,
не сохраняет настройки и не удаляет файлы.

- `ABSENT`: объект не обнаружен по доступным данным.
- `SHARED_OR_FOREIGN`: пользовательский/общий объект — сохранить.
- `UNKNOWN`: принадлежность не доказана или чтение не удалось — не удалять.

Даже узнаваемое имя, запись в журнале или содержимое не доказывают эксклюзивное владение KAS.
При успешной проверке журнала `--check` показывает записи `RECORDED`, но ничего не удаляет.
Аудитор не выводит содержимое пользовательского YAML и его секреты.

## Блокирующие режимы

~~~sh
sh uninstall.sh --remove
sh uninstall.sh --purge
~~~

Сейчас оба режима возвращают **код 3**, не выполняя действий. Это
намеренная защита для старых установок без ownership/provenance.

## Что требуется для настоящего удаления

Следующий этап #179 — вести проверяемый журнал созданных/переиспользованных
ресурсов; корректно отключать зависимости ProxyN/policy/Netfilter до остановки
Mihomo; учитывать общие пакеты, cron, существующий DNS intercept;
оставлять пользовательские YAML и бэкапы. `--purge` требует отдельного
подтверждения и резервной копии. Тесты на стенде, а не на основном роутере.

**Не выдавать `--check` за полное удаление.** В README не публикуется команда
удаления, пока она не реализована и не прошла аппаратную проверку.
