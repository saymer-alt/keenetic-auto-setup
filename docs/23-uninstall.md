# Простое удаление KAS

Из checkout этой ревизии (файлы `uninstall.sh` и `uninstall-remove.sh` рядом):

```sh
sh uninstall.sh --remove
```

Команда сначала показывает последствия и конкретный список действий/остатков.
Для выполнения нужно ввести **REMOVE**. Отказ, EOF, занятая блокировка или
неполный начальный инвентарь не разрешают удаление. `--check` и `--plan`
остаются режимами чтения; фактический актуальный план показывает `--remove`
перед подтверждением. `--purge` не реализован.

Это необратимое удаление доступной собственной части KAS. Владелец принимает
риск изменения сетевого доступа. Не требуются Doctor WARN 0, snapshot, exact-version
IPK cache, образ USB, transaction prepare или автоматический rollback.
После ошибки дальнейшие зависимые действия прекращаются. Обрыв питания
посередине операции не обеспечивает автоматического восстановления системы.

## Что разрешает удаление

Существующий `ownership.v1` подтверждает создание объекта KAS, а актуальные
проверки дополнительно проверяют его форму и известных потребителей. Отсутствующий,
повреждённый или содержащий дубликаты журнал не даёт права удалять ресурсы.
На старой установке без журнала результат — `BLOCKED`; нет `--force` и
автоматического присвоения уже существующих компонентов.

Удаляются только проверенные собственные watchdog binary/wrapper и точное
собственное cron-задание. Общие run-parts и чужие строки crontab сохраняются.
Используются существующие per-run watchdog lock, затем lifecycle-lock;
один shell удерживает обе до завершения операции. Неизвестные владельцы
блокировок не вытесняются. Новых систем lock/journal/snapshot нет.

У известного init из принадлежащего KAS пакета автозапуск отключается штатным
`ENABLED=no`, без вызова init и без сигналов. Проверяются точные SHA256
существующих generic Mihomo/MagiTrickle и KN MagiTrickle init; изменённый init
сохраняется. Пакеты с установленными зависимыми пакетами или чужими cron/init
потребителями не удаляются.

**Работающий процесс нельзя присвоить KAS по имени, PID-файлу, executable или
argv родителя. Команда его не останавливает.** Такой процесс, неизвестное
состояние `/proc` или незавершённый init startup loop сохраняют демоны,
пакеты и связанную маршрутизацию; независимая безопасная часть удаляется с
результатом `PARTIAL`. Уже запущенный startup loop может завершиться сам;
изменение ENABLED не является остановкой его shell. Если службы уже остановлены
владельцем с известным происхождением, та же команда может удалить их пакеты.
Ручная остановка не является обязательным предусловием запуска `--remove`.

Netfilter удаляется точными `-D`/`-X` только при принадлежности hook и каноническом
составе цепочки/ссылок. Общие или изменённые цепочки сохраняются вместе с
зависимой политикой/Proxy. Политика `bypass_wa` и конкретный записанный ProxyN
проверяются по своим блокам, настройкам и внешним ссылкам. Чужие ProxyN,
DNS interception, Entware, swap/zRAM и компоненты KeeneticOS не меняются.

Два пользовательских YAML (`/opt/etc/mihomo/config.yaml`,
`/opt/var/lib/magitrickle/config.yaml`) сохраняются. На время удаления пакетов
делаются только приватные копии этих двух файлов, поскольку OPKG может удалить
conffiles. Восстанавливается только отсутствующий файл; конкурентное изменение
не перезаписывается. При ошибке копия сохраняется с указанным путём. Это не
системный snapshot и не rollback. Прочие пользовательские данные не очищаются.

Общий feed MagiTrickle, flash-защита S00ubifs, binary provenance и исходный
журнал владения сохраняются: отсутствие пакета не доказывает, что они больше
никому не нужны. Остатки явно отображаются; журнал позволяет безопасно повторить
команду после частичного результата без новой системы учёта.

## Результат

| Статус | Код | Значение |
|---|---:|---|
| SUCCESS | 0 | Все доступные проверенные компоненты удалены либо уже отсутствуют |
| PARTIAL | 1 | Безопасная часть удалена/проверена; остались перечисленные общие, неизвестные или не удалённые компоненты |
| BLOCKED | 3 | Удаление не разрешено или не началось; компоненты оставлены |

Отчёт различает `REMOVED`, `DISABLED`, `LEFT`, `PRESERVED`. Любая попытка
изменения с неопределённым результатом после ошибки считается `PARTIAL`,
а не обещанием отсутствия изменений. Повторный запуск заново проверяет
состояние; автоматического resume, повторных kill и скрытого rollback нет.

PR #215/#227/#232 — отдельные результаты исследования транзакционного удаления.
Они не являются зависимостями этой команды и не сливаются автоматически.
Виртуальные и fixture-проверки не подтверждают аппаратную приёмку KN-1010.
