# KAS Web: проверка на KN-1010 (MIPSel, эксперимент)

Это отдельная необязательная панель, не переустановка KAS и не релиз.
ARM64 E2E не подтверждает работу на KN-1010. Сборка MIPSel softfloat
подготовлена для аппаратной проверки, а не объявлена принятой на устройстве.

## Комплект одной ревизии

В успешном запуске **KAS Control Center prototype** скачайте артефакт
`kas-web-kn1010-<полный SHA>` и распакуйте на компьютере. В `BUILD_INFO`
должен быть тот же `KAS_SOURCE_SHA`, а также `GOARCH=mipsle`,
`GOMIPS=softfloat`, `CGO_ENABLED=0`. В бинарник уже встроены Doctor,
импортёр и интерфейс из этой ревизии; отдельно заменять их на stable нельзя.
Комплект содержит бинарник, `kas-web-manage.sh`, эту инструкцию и `SHA256SUMS`.

## 1. Подготовка без изменения KAS

Сначала сохранить результаты и согласовать их с проверяющим:

```sh
uname -m
sed -n '1,5p' /proc/meminfo
cat /proc/swaps
df -h /opt /tmp
command -v cmp
command -v sha256sum
ip -4 addr show br0
/opt/etc/init.d/S99mihomo status
```

Также проверить отсутствие уже установленной панели, доступность SSH из Home
и свободный порт 18081. Не создавать SWAP, не менять firewall или маршруты
ради панели. Если `cmp` или `sha256sum` отсутствуют, не обходить проверки:
сначала определить подходящий штатный пакет Entware.

После проверки перенести распакованный комплект через SCP/SFTP в отдельный
каталог `/tmp/kas-web-kn1010` на роутере. Не скачивать ARM64-бинарник.

```sh
cd /tmp/kas-web-kn1010
sha256sum -c SHA256SUMS
cat BUILD_INFO
chmod 700 kas-control-center-mipsle
./kas-control-center-mipsle -h
```

Любая ошибка контрольной суммы, `Exec format error`, `Illegal instruction`
или отсутствие нужных функций — остановка проверки, без установки.

## 2. Установка и первое открытие (после допуска к аппаратному тесту)

Сохранить отдельную приватную копию действующего YAML **вне** штатного
`config.yaml.bak` и иметь проверенный путь восстановления через SSH.
Не публиковать конфиг, подписки или содержимое резервной копии в отчёте.

```sh
cd /tmp/kas-web-kn1010
sha256sum -c SHA256SUMS
binary_sha=$(awk '$2 == "kas-control-center-mipsle" {print $1}' SHA256SUMS)
sh ./kas-web-manage.sh install ./kas-control-center-mipsle "$binary_sha"
sh /opt/etc/init.d/S98kas-control-center start
sh /opt/etc/init.d/S98kas-control-center status
```

Установка не запускает панель сама, но создаёт Entware S98 init для автозапуска.
Действующие KAS/Mihomo/MT переустанавливать не требуется. Панель открывается на
`http://<фактический IPv4 br0>:18081` из доверенной Home-сети. По умолчанию
пароля KAS нет; WAN/KeenDNS в рамках этого теста не публиковать.

Сначала проверить открытие и RU/EN с выключенным экспортом имён. Затем явно
включить локальные имена и редактор (контроллер Mihomo уже должен работать):

```sh
touch /opt/etc/kas-control-center.export-names
chmod 600 /opt/etc/kas-control-center.export-names
sh /opt/etc/init.d/S98kas-control-center stop
sh /opt/etc/init.d/S98kas-control-center start
```

Настройки контроллера и его secret не менять. Если secret непустой, использовать
документированный приватный файл из `LAN.md`, не командную строку или отчёт.

## 3. Первый аппаратный проход

1. Загрузить провайдеры, сверить имена и существующий фильтр. Сложный YAML
   может быть отклонён; это не повод переписывать конфиг или ослаблять проверки.
2. Выбрать один узел одного провайдера, проверить предпросмотр и подтвердить.
   При наличии ручного regex убедиться, что оператор согласен на его замену.
3. Дождаться результата операции, независимо проверить Mihomo и фактический
   список узлов. Второй провайдер и остальные байты YAML должны сохраниться.
4. Снять фильтр через предпросмотр и подтверждение, проверить возврат узла.
   При недоступном API имён провайдеры и действие снятия должны оставаться
   доступны; успех импортёра не следует путать с доступностью API.
5. Проверить no-op, а затем stop/start самой панели: Mihomo и YAML не меняются.
   Записать RSS/HWM панели, свободную память и состояние SWAP до/после.

Во время применения не редактировать и не копировать `config.yaml` через SSH,
SCP или другие программы. Поздняя запись после финального сравнения может
быть потеряна; `.bak` её не сохраняет. Тест устаревшего конфига выполнять
отдельно: закончить внешнее редактирование **до** нажатия «Применить».
Не запускать второй Mihomo, в том числе `mihomo -t`, рядом с работающим.
Не обрывать питание и не делать reboot во время импорта.

## 4. Завершение

Обычная остановка и удаление только панели:

```sh
sh /opt/etc/init.d/S98kas-control-center stop
sh /opt/etc/init.d/S98kas-control-center remove
```

Helper сохраняет пользовательские опциональные файлы панели. Удаление панели
не восстанавливает фильтр: нужное снятие/восстановление выполнить заранее.
Не удалять lifecycle-lock/maintenance-маркеры вручную и не применять SIGKILL
к импорту. Если helper отказывает, сохранить ошибку и разобраться через SSH.

В отчёте: модель/прошивка, SHA, результаты этапов, коды ошибок без YAML/секретов,
измерения ресурсов и состояние Mihomo после удаления. Reboot, отказ питания
и намеренный rollback на железе — отдельный согласованный проход после первого.
