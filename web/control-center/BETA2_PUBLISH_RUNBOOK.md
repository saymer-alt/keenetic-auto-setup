## Почему именно этот кандидат

- `e5e8a54b41` — текущий HEAD `main` (уже включает merge PR #301 «публичное отображение
  версий с `v`» — исправление исполняемого кода панели, поэтому кандидат **должен** быть
  пересобран на нём, что и сделано: run 41099642234).
- Основной CI на этом SHA: run 41099609079 (SUCCESS).
- Независимая верификация агента (30.10.2026): все 4 артефакта скачаны, `SHA256SUMS` OK;
  control-метаданные (`kas-control-center`, `0.1.0~beta.2-1`, архитектура ABI) корректны;
  ELF соответствует заявленной архитектуре (AArch64/ELF64, ARM/ELF32/GOARM=7, MIPS32
  LE/BE, GOMIPS=softfloat, CGO_ENABLED=0); `BUILD_INFO`, `Source`, per-arch
  `manifest-canonical.json` согласованы по sha256/size/source_sha; real-opkg version ladder
  beta.1 < beta.2 < stable пройден CI.
- Сборка workflow производит только hash-checked переупаковку артефактов CI —
  непроверенная пересборка невозможна по конструкции.

3. Индекс `kas-web-channel-experimental` по-прежнему указывает на beta.1

4. GitHub `latest` — по-прежнему `v1.8.4` (ядро); ничего переименовать/переключить нельзя.
5. HEAD `main` всё ещё `e5e8a54b41…` (или уточнить run для нового SHA и перезапинить).
6. Артефакты run 41099642234 не истекли (retention 21 день от 30.10.2026).

## Действия владельца

1. От ветки `main` (SHA выше) создать ветку `ops/publish-kas-web-beta2-20261030`.
2. В workflow заполнить `SOURCE_SHA` и `VERIFIED_RUN` (значения выше).
3. Закоммитить и запушить **только** изменённый workflow — это запустит публикацию.
4. Наблюдать run; все шаги должны закончиться PASS (бэкап индекса → скачивание и
   hash-проверка 4 артефактов → сверка per-arch манифестов → публикация релиза →
   сверка релиза с манифестом байт-в-байт → переключение индекса → верификация).

## Что должно получиться после публикации

- Релиз `v0.1.0-beta.2` (prerelease, `latest=false`, target = SOURCE_SHA) ровно с 5 asset:
  4 IPK (`~` нормализован в `.` в именах) + `SHA256SUMS`; дайджесты GitHub совпадают с
  манифестом индекса.
- `kas-web-channel-experimental` — единственный asset `panel-update.json` теперь указывает
  на тег `v0.1.0-beta.2`; бэкап прежнего индекса лежит в артефактах run.
- Никакого релиза-алиаса `kas-web-ipk-<sha>` для beta.2 (workflow это запрещает).
- Панель beta.2 на пилоте: «Проверить версию панели» теперь отвечает «вы используете
  последнюю версию канала»; обновление `beta.2 → beta.3` и `beta.2 → stable` остаются
  ручными и подтвердительными.
- Документация пользователя (Draft PR #299, `docs/26-kas-web-beta-install.md`) становится
  валидной — после успешной публикации PR #299 можно выводить из Draft (ссылки в нём
  рассчитаны на опубликованный релиз).

## Откат

- Индекс: восстановить прежний `panel-update.json` (бэкап в артефактах run / содержимое
  тега `kas-web-ipk-92e301d`) через `gh release upload kas-web-channel-experimental
  panel-update.json --clobber`. Панели beta.2 при этом снова увидят beta.1 в канале и

  публикация прошла, а индекс откачен, релиз можно оставить до следующего решения.
