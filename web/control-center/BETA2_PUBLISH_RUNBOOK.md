## Текущий режим проверки

1. На NC-4210 по выходным владелец проверяет уже установленную beta.2;
   результаты заносятся в [журнал аппаратной приёмки](BETA2_OWNER_ACCEPTANCE.md).
2. Кандидат beta.3 разрабатывается в
   [Draft PR #304](https://github.com/saymer-alt/keenetic-auto-setup/pull/304)
   (переключатель темы рядом с RU/EN и редактура текстов интерфейса).
   **PR, CI или наличие исходников не означают публичного релиза beta.3.**
3. После ревью, интеграции и публикации проверенного кандидата — отдельный
   тест **beta.2 → beta.3 непосредственно через кнопку Web**, с ручным
   подтверждением и контролем runtime version, настроек, фильтров,
   Doctor и работающей сети. SSH использовать как резервный recovery, не как штатный путь обновления.
4. Нельзя заявлять аппаратный PASS до фактических результатов владельца.
   Результаты ARM64 GitHub VM/QEMU/ported E2E фиксировать отдельно.

## Release gates будущей beta.3 и последующих выпусков

1. **Source-pinned candidate:** собран из финального immutable source SHA
   после интеграции нужных изменений, не из промежуточного Draft PR.
2. **Build/verification:** корректные control-version/opkg ordering,
   ELF/ABI, `BUILD_INFO`, четыре заявленных архитектуры либо документированное
   сужение поддержки, `SHA256SUMS` и пер-архитектурные манифесты.
3. **Реальный lab-upgrade:** Web beta.2 → beta.3, detached updater,
   процесс новой версии, runtime receipt и сохранность настроек; негативные
   кейсы (скачивание, неверный SHA, ABI, Channel, lock/opkg, нехватка места,
   недоступный индекс, равная/меньшая версия).
4. **Публикация:** только по отдельному owner GO, ровно один immutable
   канонический prerelease `v0.1.0-beta.3` с нужными IPK и SHA256SUMS,
   без нового `kas-web-ipk-<sha>` alias.
5. **Атомарное переключение по смыслу:** до смены `panel-update.json`
   скачать и проверить все release assets, снять резервную копию предыдущего
   индекса; менять только experimental channel, подтвердить ссылку на новый
   релиз, иметь проверяемый путь восстановления индекса.
6. **Безопасность:** stable channel, `main`/`stable` ядра, GitHub latest,
   установленные роутеры и пользовательские YAML/пароли не менять публикацией.
   Никаких автоматических установок при проверке версии.

## Восстановление индекса после неудачной публикации beta.3

- Не удалять уже опубликованную, успешно установленную beta.2.
- При ошибке переключения вернуть **сохранённые точные байты старого
  `panel-update.json`**, а не пересоздавать его вручную и не подставлять
  устаревший test/beta.1 alias.
- Проверить совпадение SHA256 старого индекса с backup, затем корректное
  чтение beta.2 и сообщение об отсутствии обновления.
- Если новая beta уже успела установиться на устройство, не выполнять
  downgrade: отдельная диагностика и восстановление с учётом её runtime version.
- Отсутствует проверенная копия индекса/невозможно проверить источник:
  остановить дальнейшие изменения и вынести вопрос на owner review.
