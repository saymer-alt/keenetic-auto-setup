## 1. Purpose and human intent

KAS is a POSIX/BusyBox-ash toolkit for KeeneticOS+Entware: Mihomo on 127.0.0.1:7890 via Keenetic ProxyN, MagiTrickle DNS decisions, VoIP bypass, tmpfs/flash protection and watchdog. Protect connectivity and user data; do not rewrite proven architecture for elegance. Read [ARCHITECTURE.md](ARCHITECTURE.md) when changing traffic paths.

**Proof Before Build:** For new features or major integrations, reproduce a real need, consider native KeeneticOS / waiting / doing nothing, evaluate risks, cost and verifiable acceptance. Follow [docs/PROOF-BEFORE-BUILD.md](docs/PROOF-BEFORE-BUILD.md) and the [cross-project policy](https://github.com/saymer-alt/saymer-alt/blob/main/PROOF-BEFORE-BUILD.md). Routine scoped bugfixes should remain proportionate.

**KAS-AGENT-001:** Meaningful user result outranks literal checkbox compliance. For complex/risky work follow [docs/AGENT-TASK-CONTRACT.md](docs/AGENT-TASK-CONTRACT.md) and [docs/CONSTITUTION.md](docs/CONSTITUTION.md): human goal, exact refs/SHA, existing work, scope/non-goals, protected state, dependencies, negative tests, owner GO, Definition of Done. Do not infer permission from vague "clean up", "merge" or "release"; STOP only the unsafe ambiguous operation, continue safe authorized work. Do not ask already-answered questions.

## 2. Mandatory safety invariants

- **KAS-SAFETY-001 — absolute dual-swap prohibition.** Confirmed *native* zRAM + *external* storage-backed SWAP together are forbidden. Installer ERROR before mutations; Doctor FAIL; update-mihomo ERROR before binary/service mutation. NEVER downgrade to WARN, add force/exception, auto-toggle storage, or exempt a RAM class, router role or /opt mode. Preserve negative regressions. See [docs/CONSTITUTION.md](docs/CONSTITUTION.md); only a separately reviewed explicit owner decision can change it.
- Resource profile `20261012_1`: 128 MB new install experimental only if external /opt plus >=384 MB active external SWAP; missing a memory-pressure backend at 256 MB is WARN; 512 MB *requires* native zRAM **or** verified external SWAP for new install (else installer ERROR/Doctor FAIL), with no AP override; >512 MB optional. External SWAP >2 GiB is invalid for new installs. Never format, resize, mount, enable or disable SWAP/storage automatically. Legacy update behavior and nuanced warnings are in docs/06 and [platform/resource guidance](docs/agent-guidance/01-architecture-and-platforms.md).
- New external /opt requires **EXT4** and the KeeneticOS `ext`+`ext-utils` components. Internal /opt needs executable/enabled S00ubifs and real tmpfs on /opt/tmp, /opt/var/log and /opt/var/run. Verify actual deepest mounts. Do not claim storage safety from file presence.
- Preserve one-Mihomo-only process/validation, lifecycle locking, transactional config/binary/TUN migration, same-filesystem staging+atomic rename, project-state backup, rollback and prior service state. Unknown process identity => fail closed. Do not silently simplify fallback chains. See [development/safety details](docs/agent-guidance/02-development-and-safety.md).
- Watchdog: do not restart when WAN is unconfirmed; preserve checks, lock, jitter, cooldown, cron ownership and logging. `020-bypass-wa.sh`: idempotent custom mangle chain, `-C` before append, no global iptables flush. ProxyN: retain compatible legacy identities and foreign interfaces. Never rewrite live routing, firewall, DNS, persistent Keenetic configuration or services without explicit scoped operator authorization.
- KeeneticOS+Entware runtime is **not GNU/Linux**: POSIX sh/BusyBox ash; no bashisms/GNU assumptions; BusyBox 1.37 lacks `stat -c`. Verify or safely guard optional helpers (`pidof`, `ss`, `ndmq`, `timeout`). Parse each external CLI format separately: `show version` components may wrap; `show running-config` is line-semantic and must **never** be globally joined. UNKNOWN evidence is not NOT_FOUND.

## 3. Git, permissions, releases

- `main` = development; `stable` = production. Start with actual `git status`, exact branch/HEAD, issue/PR, and unrelated edits. Search indexes may lag: fetch exact file/blob by ref/SHA. Read file history before changing delicate code. Work in isolated branches; do not overwrite others, reset hard, force-push or silently move `stable`.
- **Commit/push only on explicit owner instruction.** Permission to examine, patch, open PR, merge, publish, delete, deploy and operate live routers are separate. Owner GO is required for risky history, `main → stable` promotion, tagging, release, update channels and live-router actions. Never silently switch `latest`, release pointers, IPKs or production devices.
- `main → stable` requires green CI on the exact final SHA, focused acceptance, operator review/GO; tag that exact production commit. If branch synchronization is needed after promotion, follow the established no-force policy. Before each Core release, inspect *runtime-file* drift across main/stable and report included/excluded work.
- Do not assert a FIELD PASS from Linux CI/QEMU or a release from a Draft PR. Report PLANNED, IMPLEMENTED, CI PASS, QEMU/EMULATOR PASS, FIELD PASS, MERGED and PUBLISHED separately, with concrete SHA and evidence.
- Never disclose keys, subscriptions, private configurations, WAN/router inventories. WORKING-FIRST / LICENSE AUDIT DEFERRED: don't repeatedly block independent working projects for incomplete WDTT licence inventory (KAS #126), but a non-commercial public repo does **not** grant rights to ship third-party code. Preserve notices and stop distribution of a specifically proven restricted component.

## 4. Efficient execution without losing quality

1. Determine component and current baseline (branch/ref/SHA, issue/PR, prior work). For modifications, read the affected script **in full once at that SHA** and the appropriate focused documentation; later use targeted reads/grep and re-read only on change. Do not preload all files or repeat giant logs.
2. Preserve existing fallbacks and rollback; implement the smallest change with meaningful user-facing acceptance, negative cases and the smallest lasting regression. Do not widen to unrelated tech debt. Grade outside-scope debt High/Medium/Low and report it; create an issue or TODO only with operator permission.
3. **Loop guard:** after two futile identical attempts without new SHA/environment/evidence, change hypothesis or STOP as BLOCKED. Reuse CI evidence only for compatible SHA/code/environment/scope. Cheap local tests before expensive CI/QEMU, but mandatory final checks must not be skipped. Details: [docs/agent-token-efficiency.md](docs/agent-token-efficiency.md).
4. For shell edits: `sh -n` on each changed script; POSIX/BusyBox review; focused permanent regression; `sh tests/contracts.sh` as lightweight cross-component smoke; high-risk gates according to [docs/TESTING_STRATEGY.md](docs/TESTING_STRATEGY.md). Never weaken tests merely to obtain PASS, or treat emulation as hardware proof.
5. Keep status/output colors per [docs/18-output-colors.md](docs/18-output-colors.md): green OK, cyan INFO, yellow WARN, red ERROR/FAIL, TTY-only ANSI, respect NO_COLOR/TERM=dumb, no ANSI in persisted logs. Download retry/fallback steps must remain **quiet per attempt**, with bounded error summaries.
6. Reports/handoffs should be concise and auditable: issue/PR, base/head SHA, touched scope, PASS/FAIL/NOT_TESTED with evidence, blockers, precise next step. No invented versions, tests, hardware or token metrics. Keep RU/EN README and code/docs synchronized. Historic field-model evidence is not a claim about today's home router.
